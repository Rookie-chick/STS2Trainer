# 10 · 功能 2：金币无限（零基础手把手）

> [!important] 这篇讲的不是"一个小脚本"，而是"**往 Trainer 里加一个功能**"
> 终点成品和 Plus20 Trainer 一样：**一个程序、热键开关、20 个功能**。
> 本项目的 Trainer 骨架在 `D:\sts2\教程代码\sts2trainer\`，
> 结构：`Game.cs`（只读：找对象/字段/方法）+ `Hook.cs`（注入：帧钩子/setter 钩子）+ `Program.cs`（热键与开关）。
> 每篇教程 = 教你在 `Program.cs` 里加**一组 Action**，再加一个热键。

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 金币锁在 9999999；买东西不掉钱；顶栏数字同步显示 |
| 验收标准 | ① 顶栏金币显示 `9999999` ② 外部把 `_gold` 改成 1，600ms 内回 9999999 ③ 与其它功能同时生效不崩 |
| 热键（对齐原版） | `Ctrl + Num 1` |

## 2. 原理：金币这条链的四个事实

用 ILSpy 打开 `sts2.dll`，搜 `Player` / `NTopBarGold`，能看到（`decomp\full` 里有同样内容）：

```csharp
// ① 数据：Player.cs:145
public int Gold { get => _gold; private set { if (value != Gold) { _gold = value; GoldChanged?.Invoke(); } } }

// ② 事件订阅：NTopBarGold.cs:123
public void Initialize(Player player)
{ _player = player; _currentGold = _player.Gold; _goldLabel.SetTextAutoSize($"{_currentGold}"); _player.GoldChanged += UpdateGold; }

// ③ "刷新"其实是动画：NTopBarGold.cs:136
private async Task UpdateGoldAnim()
{
    int currentGold = _player.Gold - _currentGold;      // delta
    _additionalGold = (_currentGold = currentGold);
    _currentGold = _player.Gold;
    while (_additionalGold != 0) { ... 每帧滚 1/10/75 ... _goldLabel.SetTextAutoSize($"{_player.Gold - _additionalGold}"); }
    _goldLabel.SetTextAutoSize($"{_player.Gold}");      // 滚完落到真实值
}
```

| 事实 | 影响 |
|---|---|
| **写字段不会发事件** | 和血量一样：纯写 `_gold` 画面不动 |
| **刷新是"数字滚动动画"** | 直接调 `UpdateGold` 且 delta=90 万时，要**滚 5 小时**，还会把 `_alreadyRunning` 卡死 |
| **`UpdateGold` 在 ClrMD 里常报 `0xFFFF…`**（未 JIT） | 要另找入口：**从 `GoldChanged` 委托对象里抠** |
| **动画最后一行读实时字段** | 所以"先把 `_currentGold` 设成 目标-1"就能让 delta=1，一帧滚完 |

### 2.1 委托内存布局（关键的"备用法门"）

```text
System.Delegate（.NET 9）：
  +0x00 MethodTable
  +0x08 _target        ← 订阅者对象（这里就是顶栏金币节点）
  +0x10 _methodPtr
  +0x18 _methodPtrAux  ← 本项目这里才是真入口（_methodPtr 为 0）
```

`Player.GoldChanged` 字段真实偏移 **0x40**（ClrMD 报 0x38，+8）。

## 4. 你该怎么做（在 Trainer 里加"金币锁"）

### 4.1 六步配方（以后每个功能都照这个做）

```text
① 反编译里找到"谁显示这个数字"（NTopBarGold）→ 记下刷新方法的**真实行为**
② 用 ClrMD 找到：数据字段偏移 / UI 节点实例 / 刷新方法地址（拿不到就用委托抠）
③ 在 Game.cs 的常量区登记偏移，在 Resolve() 里找到节点和方法
④ 在 Program.cs 的 actions 里加一条 Action（含开关变量）
⑤ 在热键表里加一个键
⑥ 编译 → 跑 → 看画面 → 强写值验证
```

### 4.2 第 ③ 步：`Game.cs` 里要登记的东西

```csharp
// 偏移（真实 = ClrMD 报的 + 8）
public const int OFF_PLAYER_GOLD = 0xE8;        // Player._gold
public const int OFF_PLAYER_GOLDCHANGED = 0x40; // Player.GoldChanged（委托）
public const int OFF_GOLDBAR_CURGOLD = 0x54;    // NTopBarGold._currentGold
public const int OFF_BAR_PLAYER = 0x58;         // NTopBarGold._player

// Resolve() 里：
GoldBar = FindNodeOwnedBy(T_GOLDBAR, OFF_BAR_PLAYER, OFF_BAR_PLAYER);
FnUpdateGold = Method(T_GOLDBAR, "UpdateGold");
if (FnUpdateGold == 0) FnUpdateGold = DelegateFn(Player, OFF_PLAYER_GOLDCHANGED, out _);  // ★备用法门
```

### 4.3 第 ④ 步：`Program.cs` 里加一条 Action（**这就是"功能本体"**）

```csharp
new Hook.Action{
    Name      = "金币锁",
    FlagAddr  = F(1),                                   // 开关变量（1=开 0=关）
    CheckAddr = g.Player + Game.OFF_PLAYER_GOLD,        // 读这里判断
    Target    = GOLD_VALUE,                             // 期望 9999999
    WriteAddr = g.Player + Game.OFF_PLAYER_GOLD,        // 不等于就写回
    PreAddr   = g.GoldBar + Game.OFF_GOLDBAR_CURGOLD,   // ★调用前把 _currentGold 设成 目标-1
    PreValue  = GOLD_VALUE - 1,                         //   让"滚动动画"delta=1，一帧滚完
    CallThis  = g.GoldBar,
    CallFn    = g.FnUpdateGold,                         // 调刷新方法
},
```

### 4.4 第 ⑤ 步：热键

```csharp
// keys 数组里加一项（顺序和 names、state 对应）
(VK_NUMPAD1, true),      // Ctrl + Num1
// names 数组里加 "金币锁"
```

热键轮询很简单：主线程 `while(true)` 里每 40ms 用 `GetAsyncKeyState(vk)` 查一次按键，
**只在"从没按到按下"的那一瞬**翻转开关变量：`Hook.WriteI32(h, F(i), state ? 1 : 0)`。

> [!tip] 为什么"开关"只是写一个 int
> 代码洞里每个动作都以 `mov rax,开关地址; cmp dword [rax],0; je 跳过` 开头。
> 所以开/关功能 = 往那 4 个字节写 1/0，**不用重新打补丁**，也不会因为反复打补丁把游戏搞崩。

## 5. 验证

| 步骤 | 命令 | 期望 |
|---|---|---|
| 看字段 | Trainer 启动时打印的 `Gold =` | 等于画面金币 |
| 看画面 | 截图顶栏 | 金币 `9999999` |
| 强写验证 | `pokegold 1` | 600ms 后回 9999999 |
| 开关验证 | 按 `Ctrl+Num1` | 控制台打印 `[关] 金币锁`，再把金币写成 1 不会被补回 |

## 6. 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 启动就报 `✗ 这个挂点已经被别的补丁占用了` | 上次 Trainer 被强杀，补丁还在游戏里 | **重启游戏**（或按 09 篇第 13 节把原字节写回） |
| 金币数字"滚"很久才停 | 忘了 `PreAddr/PreValue` 那一步 | 补上：`_currentGold = 目标-1` |
| `UpdateGold=0xFFFF…` | 方法没 JIT | 用 `DelegateFn(Player, 0x40, ...)` 从委托抠 |
| 开了功能但画面不变 | 挂点没被调用（进战斗才有 `NTargetManager`） | 进战斗后再开 |
| 一开某项功能游戏就退出 | 我们调的刷新方法内部抛异常（裸机器码没有 unwind 信息） | 换更轻的方法（见 [[13-复刻-无限星星]] 的踩坑） |

## 7. 回滚

- Trainer 里按 `Q`：会 `Hook.Restore()` 把两个挂点写回原指令；
- 直接关窗口 / 强杀：**补丁会留在游戏里**，直到重启游戏（内存补丁不落盘，重启即恢复）。

## 8. 三类结论

### ✅ 已验证

| 结论 | 证据 |
|---|---|
| `_gold` 真实偏移 **0xE8** | 机器码 `8B 89 E8 00 00 00`（`NTopBarGold.Initialize`）+ 画面一致 |
| `_currentGold` **0x54**、`GoldChanged` **0x40** | 同上机器码 `89 4B 54`；委托 `_target` = 顶栏节点 |
| 委托 `_methodPtrAux` 可当调用入口 | Trainer 里 `UpdateGold` 就是这么拿到的，画面立刻变 9999999 |
| 动画 delta 花招有效 | `_currentGold = 目标-1` 后一帧到位，无长时间滚动 |
| 一个帧钩子可挂多个功能且互相独立 | 310 字节代码洞、4 个动作 + 1 个 setter 钩子同时生效 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| ClrMD 一定能给 `UpdateGold` 地址 | 常常是 `0xFFFFFFFFFFFFFFFF`（未 JIT） |
| 直接调 `UpdateGold` 刷大额 | delta 90 万 → 每帧滚 75 → 要滚 5 小时 |
| 只写 `_gold` 就能改画面 | 顶栏文字不动（事件没发） |
