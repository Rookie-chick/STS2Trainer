# 15 · 功能 7：卡牌奖励必升级（奖励里的卡都带 +）

> [!important] 这一篇解决"decimal 返回值怎么写"
> 上一篇的 `bool` 走 `eax`；这一篇的返回值是 **decimal（16 字节）**——
> x64 约定下它不走寄存器：调用者先给一块 16 字节缓冲，**指针放在 `rcx`**，
> 方法把结果写进去，再把指针放回 `rax`。
> 学会这一条，**倍率 / 价格 / 分数**那一大类（20、21、23、24、26、27 篇）全都能做。
> 热键：`Num 6`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 战斗奖励里出现的卡牌**默认就是升级版**（带 `+`）；商店里卖的卡也是升级版 |
| 验收标准 | ① 奖励卡牌左上角有 `+` ② 商店卡也带 `+` ③ 关掉恢复 |
| 热键 | `Num 6` |

## 2. 原理

```csharp
// MegaCrit.Sts2.Core.Hooks/Hook.cs
public static decimal ModifyCardRewardUpgradeOdds(IRunState runState, Player player, CardModel card, decimal originalOdds)
{
    decimal num = originalOdds;
    foreach (AbstractModel item in runState.IterateHookListeners(null))
        num = item.ModifyCardRewardUpgradeOdds(player, card, num);   // 每个模型都能改这个概率
    return num;                                                      // ← 返回 0~1
}
```

调用方大致是 `if (rng.NextFloat() < Hook.ModifyCardRewardUpgradeOdds(...)) 这张卡升级;`
⇒ 让它返回 **1（100%）** 就必升级。

> [!tip] 为什么 hook 汇总点而不是每个模型
> `AbstractModel.ModifyCardRewardUpgradeOdds` 是虚方法，有多个实现（遗物/诅咒各改各的）。
> `Hook.ModifyCardRewardUpgradeOdds` 是**唯一汇总点**，改一个就够。

## 4. 你该怎么做：代码怎么写

### 4.1 decimal 的内存布局（记住这个，一辈子用得上）

```text
decimal = 16 字节 = 4 个 int
  +0x00 lo     低 32 位
  +0x04 mid    中 32 位
  +0x08 hi     高 32 位
  +0x0C flags  bit16~23 = scale（小数点位置），bit31 = 符号

  1     = lo=1,    mid=0, hi=0, flags=0x00000000
  1.0   = lo=10,   mid=0, hi=0, flags=0x00010000 (scale=1)
  0     = lo=0,    mid=0, hi=0, flags=0
  9999  = lo=9999, mid=0, hi=0, flags=0
```

> 想改成 50%？`0.5m` = `[5, 0, 0, 0x00010000]`。别手算，用 C# 的 `decimal.GetBits(0.5m)`。

### 4.2 钩子：把返回值写成 1

```csharp
public static byte[] InstallForceDecimalReturnHook(IntPtr h, ulong methodAddr, ulong flagAddr, decimal value)
{
    int[] parts = decimal.GetBits(value);        // [lo, mid, hi, flags]
    var head = Read(h, methodAddr, 16);
    int n = PrologueLen(head);
    var original = new byte[n]; Array.Copy(head, 0, original, 0, n);
    ulong cave = AllocNear(h, methodAddr, 0x1000);

    var c = new List<byte>();
    B(0x50);                                     // push rax
    B(0x48, 0xB8); I64(flagAddr);                // mov rax,&开关
    B(0x83, 0x38, 0x00);                         // cmp dword [rax],0
    int jeAt = c.Count; B(0x74, 0x00);           // je 原样
    B(0x58);                                     // pop rax
    B(0xC7, 0x01); I32(parts[0]);                // mov dword [rcx],   lo
    B(0xC7, 0x41, 0x04); I32(parts[1]);          // mov dword [rcx+4], mid
    B(0xC7, 0x41, 0x08); I32(parts[2]);          // mov dword [rcx+8], hi
    B(0xC7, 0x41, 0x0C); I32(parts[3]);          // mov dword [rcx+0xC], flags
    B(0x48, 0x89, 0xC8);                         // mov rax,rcx   ← ★必须
    B(0xC3);                                     // ret
    // …原样路径 + jmp 回 方法+n（同 14 篇）…
    return original;
}
```

关键片段：

```asm
C7 01 01 00 00 00        mov dword [rcx],1       ; lo
C7 41 04 00 00 00 00     mov dword [rcx+4],0     ; mid
C7 41 08 00 00 00 00     mov dword [rcx+8],0     ; hi
C7 41 0C 00 00 00 00     mov dword [rcx+0xC],0   ; flags=0  → 数值 1
48 89 C8                 mov rax,rcx             ; 返回缓冲指针
C3                       ret
```

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 返回值被当成 0 | `flags` 写错（scale 放错位） | 用 `decimal.GetBits()`，别手算 |
| 找错重载 | 没效果甚至崩 | 认准 4 参数那个 |
| 忘了 `mov rax,rcx` | 调用方拿到垃圾 decimal → 诡异/崩 | decimal 返回必须把指针放回 rax |
| 未 JIT | 0xFFFF | 延迟安装（14 篇 4.2） |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| `Hook.ModifyCardRewardUpgradeOdds(IRunState, Player, CardModel, decimal)` 是唯一汇总点，返回 0~1 概率 | 反编译源码（遍历 hook listeners 累加） |
| decimal = 4×int(lo/mid/hi/flags)，scale 在 flags bit16~23 | .NET 规范；`decimal.GetBits()` 自测 |
| x64 上 decimal 返回值走隐藏返回指针 rcx，并需把指针放回 rax | ABI |
