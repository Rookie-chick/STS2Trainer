# 08 · 教程总纲：20 个功能怎么一个个做出来

> [!important] 这套教程的目标
> 做出一个**和 Plus20 Trainer 一样的东西**：一个程序、热键开关、20 个功能。
> 但教程的重点是**教你"怎么自己找出来"**——因为游戏一更新、方法一改名，抄来的代码就废了，
> 而"六步法 + 三种钩子"这套流程永远有效。

## 2. ★ 六步法：每个功能都照这个流程走

```text
① 定目标：这个功能"改了哪个数字/哪个行为"？（写下来）
② 找显示/使用方：在 ILSpy 里搜这个数字的 UI 文字（SetTextAutoSize / Text =），
   或搜这个行为的判断（if (...) return true/false）→ 找到"最终读值/做决定"的那个方法
③ 找数据：用 ClrMD 找对象实例 + 字段偏移（记住 ClrMD 报的 offset 要 +8）
④ 选钩子：看目标方法长什么样 → 按第 3 节的决策树选 帧钩子 / setter / 强制返回
⑤ 写代码：在 Trainer 里加一条 Action 或一次 Install*，加热键
⑥ 验证：先看画面，再用"强写值"验锁，最后反复开关验稳定性
```

### 2.1 第 ② 步的四个关键词（ILSpy 里 Ctrl+F 搜）

| 关键词 | 命中什么 | 例子 |
|---|---|---|
| `SetTextAutoSize` / `Text =` | **改 UI 文字**的方法 | `NTopBarHp.UpdateHealth`、`NEnergyCounter.RefreshLabel` |
| `Invoke(` | **事件回调**（注意：不一定刷 UI！） | `OnEnergyChanged` 只放特效 |
| `return true` / `? true : false` | **做决定**的方法（适合"强制返回"） | `PotionRewardOdds.Roll`、`ShouldTakeExtraTurn` |
| `decimal` / `float` | 数值计算/倍率类 | `ModifyDamage`、`GetBaseOdds` |

### 2.2 ★ 第 ③ 步：查方法前先想一件事——它是静态类吗

```csharp
// 错误做法：只从"堆里的实例"取 ClrType
if (!Heap.TryGetValue(typeName, out var l) || l.Count == 0) return 空;   // Hook / ScoreUtility 永远空

// 正确做法：堆里没有就按模块类型表查（静态类也在里面）
foreach (var m in Runtime.EnumerateModules())
{
    var t = m.GetTypeByName(typeName);
    if (t != null) return t;
}
```

> [!danger] 这一条不写，会白丢 6 个功能
> `Hook` / `ScoreUtility` 都是 **static class**，没有实例 ⇒ 堆里搜不到 ⇒
> `ModifyDamage`、`ModifyCardRewardUpgradeOdds`、`ShouldTakeExtraTurn`、`ModifyMerchantPrice`、
> `ModifyMaxEnergy`、`CalculateScore` **全都查不到**，UI 上表现为"永远未JIT"。
> 详细现场与自查命令见 [[29-踩坑-五个真坑（静态类-残留补丁-未JIT-只写值-decimal右移）]]。

### 2.3 ClrMD 常用命令（本仓库工具）

```powershell
$d = "$env:LOCALAPPDATA\Microsoft\dotnet\dotnet.exe"
& $d run --project D:\sts2\clr\sts2clr -- <pid> types   Odds        # 找类型全名
& $d run --project D:\sts2\clr\sts2clr -- <pid> dump    <类型全名>    # 列字段 + ClrMD 偏移
& $d run --project D:\sts2\clr\sts2clr -- <pid> methods <类型全名> <方法名>   # 方法地址 + 前 48 字节
& $d run --project D:\sts2\clr\sts2clr -- <pid> procscan Nodes       # 找"每帧都跑"的候选挂点
& $d run --project D:\sts2\clr\sts2clr -- <pid> raw     <地址> <长度>  # 十六进制 dump
& $d run --project D:\sts2\clr\sts2clr -- <pid> gdel                 # 从委托里抠方法入口
```

> [!danger] 两条铁律
> 1. **ClrMD 报的字段偏移要 +8**（对象 +0x00 是 MethodTable，+0x08 才是第一个字段）。
> 2. **`0xFFFFFFFFFFFFFFFF` 不是地址**，是"这个方法没 JIT"。把它当地址 `call` 会**直接崩游戏**。

## 3. ★ 三种钩子：怎么选（决策树）

```text
目标方法长什么样？
│
├─ 返回 bool / int / enum，而且"返回什么就决定游戏怎么做"
│     ⇒ 【强制返回】入口写 mov eax,值; ret
│        优点：最安全（不执行原方法体、不调任何托管方法）
│        例：PotionRewardOdds.Roll → true；UnknownMapPointOdds.Roll → 3
│
├─ 是 setter（值从参数进来），比如 set_Xxx(int value)
│     ⇒ 【setter 钩子】把 edx 改成固定值，然后继续执行原方法
│        优点：事件照发、UI 自动刷；缺点：只对"没被内联"的方法有效
│        例：Creature.set_Block
│
├─ 返回 float / decimal（倍率、概率、价格…）
│     ⇒ 【强制返回】但返回寄存器不同：float 用 xmm0；decimal 用隐藏返回指针 rcx
│        例：CardRarityOdds.GetBaseOdds（float）、ModifyMerchantPrice（decimal）
│
└─ 改完数据还得让 UI 知道（UI 只在事件里刷新）
      ⇒ 【帧钩子】挂一个每帧都跑的方法（如 NTargetManager._Process），
         代码洞里：值不对就写回去 → 调一次刷新方法 → 跳回原方法
         优点：能同时管很多字段；缺点：要挑对刷新方法（挑错会崩，见 13 篇）
```

### 3.1 四种返回值的机器码写法（直接抄）

```asm
; ① 返回 bool / int / enum（返回值在 eax）
B8 01 00 00 00      mov eax,1
C3                  ret

; ② 返回 float（返回值在 xmm0）
B8 00 00 7A 44      mov eax,0x447A0000     ; 999.0f 的位模式
66 0F 6E C0         movd xmm0,eax
C3                  ret

; ③ 返回 double（xmm0，8 字节）
48 B8 00 00 00 00 00 00 00 00   mov rax,<double 位模式>
66 48 0F 6E C0                  movq xmm0,rax
C3                              ret

; ④ 返回 decimal（16 字节，走"隐藏返回指针 rcx"）
;    decimal 内存布局：+0x00 lo(int) / +0x04 mid(int) / +0x08 hi(int) / +0x0C flags(scale 在 bit16-23)
C7 01 00 00 00 00            mov dword [rcx],0        ; lo   = 0      ← 例如"免费"就写 0
C7 41 04 00 00 00 00         mov dword [rcx+4],0      ; mid  = 0
C7 41 08 00 00 00 00         mov dword [rcx+8],0      ; hi   = 0
C7 41 0C 00 00 00 00         mov dword [rcx+0xC],0    ; flags= 0
48 89 C8                     mov rax,rcx              ; 按约定把返回缓冲指针放回 rax
C3                           ret
```

### 3.2 改「decimal 参数」的机器码（改伤害/价格用）

方法签名里 `decimal amount` 在 x64 上**只传指针**（`rdx` = 指向 16 字节 decimal）。

```asm
; 例：把 amount 直接改成 9999（伤害/倍率用）
C7 02 0F 27 00 00      mov dword [rdx],9999      ; lo
C7 42 04 00 00 00 00   mov dword [rdx+4],0       ; mid
C7 42 08 00 00 00 00   mov dword [rdx+8],0       ; hi
C7 42 0C 00 00 00 00   mov dword [rdx+0xC],0     ; flags(scale=0)
```

> 想做"倍率"就对 lo 做乘法（仅当 scale=0、mid/hi=0，即整数伤害时成立）：
> `imul eax,[rdx],10` 然后写回 `[rdx]`。要严谨就调 `System.Decimal.op_Multiply`（进阶，见 20 篇）。

## 4. 代码骨架：加一个功能要动哪三处

```csharp
// ① Game.cs —— 登记常量 + 在 Resolve() 里取地址
public const int OFF_XXX = 0x??;                 // 真实偏移 = ClrMD + 8
FnXxx = Method(T_XXX, "MethodName");             // ClrMD 查得到就用这个
if (FnXxx == 0) FnXxx = DelegateFn(obj, OFF_DELEGATE, out _);   // 查不到就从委托抠

// ② Program.cs —— 加一条 Action（帧钩子）或一次 Install（setter/强制返回）
var xxxOrig = Hook.InstallForceReturnHook(h, g.FnXxx, F(6), 1);   // 例：强制返回
// 或
actions.Add(new Hook.Action{ FlagAddr=F(6), CheckAddr=..., Target=..., WriteAddr=..., CallThis=..., CallFn=... });

// ③ Program.cs —— 加热键 + 退出还原
(VK_NUMPAD5, false)                               // keys
Hook.Restore(h, g.FnXxx, xxxOrig);                 // 退出时
```

## 5. 验证（不用一直开着游戏也能验）

| 层级 | 怎么验 | 判据 |
|---|---|---|
| 静态 | `methods` 命令看入口字节 + 补丁回读 | 入口变成 `E9 …`，`回读` 一致 |
| 数值 | `poke*` 强写字段，600ms 后回读 | 回到锁定值 = 锁生效 |
| 画面 | 截图 + `crop.py` 放大 | 数字/图标变成目标值 |
| 行为 | 触发一次真实事件（受一次伤 / 打完一场 / 进商店） | 效果符合预期 |
| 稳定 | 反复按热键开关 5 次 + 放置 2 分钟 | 不崩、不失效 |

> [!warning] 代码洞里调托管方法的红线（见 13 篇）
> 如果目标方法**可能抛异常**（碰 null、碰已释放节点），异常穿不过我们"没有 unwind 信息"的裸机器码 ⇒ **进程直接死**。
> 优先选：不调方法的（强制返回 / setter 改参数）> 调纯计算方法的 > 调会碰节点/动画的。

## 6. 三类结论怎么写（每篇结尾都照这个格式）

| 类别 | 含义 |
|---|---|
| ✅ 已验证 | 在本机真跑过、有输出/截图 |
| ❌ 已证伪 | 试过、失败，写清现象与根因 |
| ⏳ 待验证 | 方法已定位、代码已写好，但没实测；**必须附验证步骤** |

> [!tip] 为什么必须这么分
> 这份库是拿来"照着做"的。把没验证的东西写成"已验证"，下一个照着做的人会浪费几小时。
> 宁可写"⏳ 待验证 + 三步验证法"，也不要含糊。
