# 16 · 功能 8：卡牌奖励必是最高稀有度

> [!important] 这一篇补上第三种"返回寄存器"：**float 在 `xmm0`**
> `bool/enum/int` → `eax`；`decimal` → 隐藏指针 `rcx`；**`float` → `xmm0`**。
> 三种都学会，遇到任何"算个概率/倍率"的方法都能照抄。
> 热键：`Num 7`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 战斗奖励里出现的卡牌，稀有度必为 **Rare**（最高） |
| 验收标准 | ① 打完一场，奖励卡都是 Rare ② 连打 3 场都是 ③ 关掉恢复 |
| 热键 | `Num 7` |

## 2. 原理

```csharp
// MegaCrit.Sts2.Core.Odds/CardRarityOdds.cs
private static float GetBaseOdds(CardRarityOddsType type, CardRarity rarity) { ... }   // 返回概率阈值

// 掷骰子处（同一个类）
float num2 = GetBaseOdds(type, CardRarity.Rare) + offset;
if (num < num2) return CardRarity.Rare;                                   // ← 先判 Rare
if (num < GetBaseOdds(type, CardRarity.Uncommon) + num2) return CardRarity.Uncommon;
return CardRarity.Common;
```

`num` 是 0~1 的随机数。**让 `GetBaseOdds` 返回 999** ⇒ `num < 999` 永远成立 ⇒ 一进来就命中 Rare。

> [!tip] 为什么返回 999 而不是 1
> 它返回的是"阈值"不是"概率"。返回 1 时，`num` 若恰好接近 1 就可能不中；返回 999 必中。

## 4. 你该怎么做：代码怎么写

### 4.1 float 返回值的机器码

```asm
B8 00 00 7A 44        mov  eax,0x447A0000    ; 999.0f 的 IEEE754 位模式
66 0F 6E C0           movd xmm0,eax          ; 搬进 xmm0
C3                    ret                     ; float 返回值就在 xmm0
```

常用位模式（拿不准就用 `BitConverter.SingleToInt32Bits(v).ToString("X")` 现算）：

```text
0.5f  = 0x3F000000     1.0f = 0x3F800000     2.0f  = 0x40000000
10.0f = 0x41200000     999f = 0x447A0000
```

### 4.2 钩子（14 篇的模板，只改返回那 3 条）

```csharp
public static byte[] InstallForceFloatReturnHook(IntPtr h, ulong methodAddr, ulong flagAddr, float value)
{
    int bits = BitConverter.SingleToInt32Bits(value);
    // …
    B(0x50);                            // push rax
    B(0x48, 0xB8); I64(flagAddr);       // mov rax,&开关
    B(0x83, 0x38, 0x00);                // cmp dword [rax],0
    int jeAt = c.Count; B(0x74, 0x00);  // je 原样
    B(0x58);                            // pop rax
    B(0xB8); I32(bits);                 // mov eax,999.0f 的位
    B(0x66, 0x0F, 0x6E, 0xC0);          // movd xmm0,eax
    B(0xC3);                            // ret
    // …原样路径 + jmp 回 方法+n…
}
```

## 5. 怎么验证

| 步 | 操作 | 期望 |

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 用 `mov eax,999`（整数值） | 被当 float 位模式解释 ⇒ 是 NaN 或极小值，无效 | 必须写**位模式** |
| 改错方法（改 Roll 而不是 GetBaseOdds） | 可能崩（Roll 里有记录/动画） | 只改"纯计算"的 GetBaseOdds |
| 未 JIT | 0xFFFF | 延迟安装（14 篇） |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| 稀有度阈值由 `CardRarityOdds.GetBaseOdds(type, rarity)` 的返回值决定 | 反编译 `Roll`：`if (num < GetBaseOdds(Rare)+offset) return Rare;` |
| float 返回值在 `xmm0`，可用 `movd xmm0,eax` 构造 | x64 ABI |
| 返回大阈值 ⇒ 必中 Rare | `num` 是 0~1 随机数 |
