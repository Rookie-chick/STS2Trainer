# 11 · 功能 3：无限护盾（零基础手把手）

> [!important] 这篇教第二种钩子：**setter 钩子**
> 前两个功能都是"帧钩子 + 轮询"（每帧检查血/金币，不对就写回去）。
> 护盾能用更漂亮的办法：`Creature.set_Block` 是**有独立机器码的真方法**，
> 直接在它入口把"新值"参数 `edx` 改成 9999 就行 —— **事件照发、UI 自动刷、零轮询**。
> 热键：`Num 2`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 护盾永远 9999，敌人打不穿；显示在角色血条左边的盾牌数字上 |
| 验收标准 | ① 盾牌数字 `9999` ② 外部把 `_block` 改成 1，600ms 内回 9999 ③ 敌人**不会**跟着变 9999 |
| 热键 | `Num 2` |

## 2. 原理：为什么这次能"拦参数"

```csharp
// Creature.cs:44
public int Block
{
    get => _block;
    private set
    {
        if (value < 0) throw new ArgumentException("Block must be positive", "value");
        if (_block != value) { int b = _block; _block = value; this.BlockChanged?.Invoke(b, _block); }
    }
}
// 护盾被打：Creature.cs:430
public decimal DamageBlockInternal(decimal amount, ValueProp props)
{ decimal num = (props.HasFlag(ValueProp.Unblockable) ? 0m : Math.Min(Block, amount)); Block -= (int)num; ... }
```

- 所有护盾变化最终都走 `set_Block` ⇒ **拦它一个就够**。
- 它是"值从参数进来"的方法 ⇒ 把 `edx`（第 2 个参数）改成 9999，方法自己会：写字段 → 值变了 → 发 `BlockChanged` → UI 自动更新。

> [!tip] 为什么 `set_Block` 能挂、`set_CurrentHp` 不能
> 两者代码几乎一样，但 `set_CurrentHp` 的所有调用点被 JIT **内联**了（ClrMD 报 `0xFFFFFFFFFFFFFFFF`，没有独立机器码）；
> `set_Block` 调用点多、函数体更大，JIT **保留成独立方法** ⇒ 入口存在，可以挂。
> 判断办法：`Game.Method(...)` 返回 0 就是挂不了。

### 2.1 setter 钩子长什么样

```asm
; 挂在 Creature.set_Block 入口（原 6 字节：56 53 48 83 EC 28 = push rsi;push rbx;sub rsp,28h）
50                        push rax
48 B8 <开关变量地址>       mov  rax,&flag
83 38 00                  cmp  dword [rax],0
74 xx                     je   原样执行              ; 功能关着 → 什么都不做
48 B8 <玩家Creature>       mov  rax,玩家Creature
48 39 C1                  cmp  rcx,rax
75 xx                     jne  原样执行              ; 不是玩家 → 放行（敌人/宠物不受影响）
BA 0F 27 00 00            mov  edx,9999             ; ★把"新护盾值"改成 9999
原样执行:
58                        pop  rax
56 53 48 83 EC 28         原 6 字节（补回来）
E9 <rel32>                jmp  回 set_Block+6
```

## 4. 你该怎么做（在 Trainer 里加 setter 钩子）

### 4.1 第 ①-③ 步：确认方法可挂 + 登记

```powershell
# 用完整工具确认它有独立机器码（不是 0xFFFF）
dotnet run --project D:\sts2\clr\sts2clr -- <pid> methods MegaCrit.Sts2.Core.Entities.Creatures.Creature set_Block
```

```text
Creature::set_Block native=0x7FF7CA3C3950
  bytes: 56 53 48 83 EC 28 85 D2 7C 3C 44 8B 81 80 00 00 00 ...
         └push rsi/push rbx/sub rsp,28h┘ └test edx,edx;jl┘ └mov r8d,[rcx+80h]┘
```

一次读三种信息：① 序言 6 字节可整段覆盖 ② `[rcx+0x80]` 就是 `_block`（ClrMD 报 0x78，**+8**）③ 事件委托在 `[rcx+0x08]`。

`Game.cs` 里登记：

```csharp
public const int OFF_BLOCK = 0x80;   // Creature._block
// Resolve() 里：
FnSetBlock = Method(T_CREATURE, "set_Block");
```

### 4.2 第 ④ 步：装钩子（`Program.cs`）

```csharp
// 护盾不用"帧动作"，直接装 setter 钩子；开关变量用 F(4)
var blockOrig = Hook.InstallSetterHook(h, g.FnSetBlock, g.Creature, SHIELD_VALUE, F(4));
```

`Hook.InstallSetterHook` 干的事：
1. 读入口 16 字节 → `PrologueLen()` 算出能覆盖 ≥5 字节的整指令长度（这里 6）
2. 附近分配代码洞 → 拼上面那段机器码
3. 把入口前 n 字节改成 `E9 <rel32> + nop…`，`FlushInstructionCache`
4. 返回**原始字节**，退出时 `Hook.Restore()` 写回去

### 4.3 第 ⑤ 步：热键

```csharp
(VK_NUMPAD2, false),   // Num 2 → 护盾
```

### 4.4 为什么还要"帧钩子的第 5 个动作"？

护盾初始是 0，`set_Block` 只在"值变了"时发事件 ⇒ 界面一开始没有盾牌。
所以本项目里还有一条**踢一脚**的动作（`FlagAddr=F(4)`，`CheckAddr=_block`，`WriteAddr=0`，`CallFn=set_Block`），
它发现护盾不是 9999 就**调一次 `set_Block`** 让 setter 自己写 + 发事件。

> [!warning] 注意别写成死循环
> 如果这条动作"先写字段再调 set_Block"，setter 会看到值没变直接 return，事件永远不发；
> 正确做法是 **`WriteAddr = 0`**（不写），把写入交给 `set_Block` 自己做。

## 5. 验证

| 步骤 | 命令/操作 | 期望 |
|---|---|---|
| 看画面 | 截图血条左侧 | 盾牌 `9999` |
| 强写 | `pokesh 1` | 600ms 后回 9999 |
| 敌人对照 | 看敌人血条 | **没有**盾牌数字 |
| 开关 | 按 `Num 2` | 控制台 `[关] 无限护盾`；再强写就不会被补回 |

## 6. 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `FnSetBlock = 0` | 方法没 JIT（这一局还没人加过护盾） | 进战斗打一回合再来 |
| 盾牌数字出来了但敌人也有 | this 门禁没写对 | 检查 `cmp rcx,rax` 那两行 |
| 装完盾牌不显示 | 少了"踢一脚"的动作 | 加 `WriteAddr=0` 的帧动作 |
| 一开就崩 | 代码洞没保存 `rax` | 入口 `push rax`、出口 `pop rax`（本项目已带） |

## 7. 回滚

按 `Q`（会 `Restore` 两个挂点）；强杀则重启游戏。

## 8. 三类结论

### ✅ 已验证

| 结论 | 证据 |
|---|---|
| `set_Block` 有独立机器码，可挂 | `native` 非 0；入口 `56 53 48 83 EC 28` |
| `_block` 真实偏移 **0x80** | 机器码 `44 8B 81 80 00 00 00` / `89 91 80 00 00 00` |
| this 门禁有效 | 装上后只有玩家出现盾牌 9999 |
| 强写护盾会被补回 | `pokesh 1` → 600ms 回 9999 |
| setter 钩子 + 帧钩子可共存 | 同一进程里 4 个帧动作 + 1 个 setter 钩子稳定运行 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| `set_CurrentHp` 也能用同样办法挂 | 它是 `0xFFFF…`（被内联），只有没被内联的 setter 才行 |
| 只写 `_block` 就长期有效 | 下一次 `set_Block`（清空/消耗）会覆盖掉 |

### ⏳ 待验证

| 结论 | 怎么验 |
|---|---|
| 敌人真打过来时护盾不掉 | 结束一回合让敌人攻击，看盾牌是否保持 9999 |
