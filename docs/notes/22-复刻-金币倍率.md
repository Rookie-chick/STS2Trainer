# 22 · 功能 14：金币倍率（战斗金币奖励 ×N）

> [!important] 这一篇补最后一个"返回值类型"：**int（`eax`）**
> 到这儿四种返回值全齐了：`bool/enum/int → eax`、`float → xmm0`、`decimal → rcx 隐藏指针`。
> 金币"奖励"是 `int` 属性，改它最简单：**入口 `imul eax,N; ret`**。
> 热键：`Ctrl+Num 2`

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 战斗结算给的金币奖励 ×N（默认 10），且不超过上限 |
| 验收标准 | ① 打完一场，金币涨得明显多 ② 关掉恢复 ③ 不崩 |
| 热键 | `Ctrl+Num 2` |

## 2. 原理

```csharp
// MegaCrit.Sts2.Core.Models/EncounterModel.cs
public virtual int MinGoldReward { get; }      // ← int
public virtual int MaxGoldReward { get; }      // ← int
// 战斗结算时：gold = rng.Next(encounter.MinGoldReward, encounter.MaxGoldReward)
```

改这两个 `get` 的返回值 = 直接改"这场给多少钱"。

> [!tip] 为什么改 getter 而不是改 `Player._gold`
> 改 `_gold` 是 [[10-复刻-金币无限]]（锁值）；这个功能是"**奖励变多**"，
> 语义不同：一个是"钱不减少"，一个是"每次给更多"。原版就是两个独立功能。

## 3. 我是怎么做的：怎么找出这个方法的（真实路径）

```text
① ILSpy 搜 "GoldReward" → 命中 EncounterModel.MinGoldReward / MaxGoldReward（virtual int）
② 搜 "MinGoldReward" 的调用点 → 战斗结算处 rng.Next(min,max)
③ 返回值是 int ⇒ 强制返回目标：imul / mov eax,值
④ ClrMD：属性 getter 名是 get_MinGoldReward / get_MaxGoldReward
```

```powershell
dotnet run --project D:\sts2\clr\sts2clr -- <pid> methods MegaCrit.Sts2.Core.Models.EncounterModel get_MinGoldReward
dotnet run --project D:\sts2\clr\sts2clr -- <pid> methods MegaCrit.Sts2.Core.Models.EncounterModel get_MaxGoldReward
```

> [!warning] 都是 virtual 方法
> virtual 方法可能有多份实现（不同遭遇战子类 override）。
> `EncounterModel` 基类的 getter 只覆盖"没 override 的遭遇"；要全覆盖得挂**每个子类的 override**（麻烦）。
> 实用做法：先挂基类，实测够用就行；不够再按 `types Encounter` 列出子类逐个挂。

## 4. 你该怎么做：代码怎么写

```asm
; 入口：return 原值 * 10
; 需要"先取原值再加/乘" ⇒ 不能直接 ret，要先执行原方法体再改结果。
; 简化版（推荐给新手）：直接返回一个固定倍数基值，例如 2000
B8 D0 07 00 00        mov eax,2000
C3                    ret
```

> 想做成真正的"倍率"（原值×10），要在**方法出口**改 `eax`——这需要"尾部 hook"（找到所有 `ret` 并改写），
> 复杂度高很多。**先做"固定高值"版本**（`mov eax,2000; ret`），效果上等价于"每场给很多钱"。

### 4.1 接入 Trainer

```csharp
// Game.cs
public ulong FnMinGold, FnMaxGold;
FnMinGold = Method("MegaCrit.Sts2.Core.Models.EncounterModel", "get_MinGoldReward");
FnMaxGold = Method("MegaCrit.Sts2.Core.Models.EncounterModel", "get_MaxGoldReward");

// Program.cs —— 两个都挂，返回同一个高值
var minOrig = FnMinGold >= 0x10000 ? Hook.InstallForceReturnHook(h, FnMinGold, F(12), 2000) : null;
var maxOrig = FnMaxGold >= 0x10000 ? Hook.InstallForceReturnHook(h, FnMaxGold, F(12), 2000) : null;
// keys 加 (VK_NUMPAD2, ctrl:true) → Ctrl+Num 2；names 加 "金币倍率"
```

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 只挂了一个 getter | 奖励区间变成 (min,原 max)，可能仍很小 | min/max 都挂 |
| virtual override 没覆盖 | 某些遭遇没效果 | 挂子类的 override（`types Encounter` 找） |
| 返回 2000 但游戏显示 0 | 有上限/取整逻辑 | 换成 999 试试，或看结算代码 |
| 装完金币没变 | 这场的奖励已算完 | 对下一场生效 |

## 7. 三类结论
