# 72 · 原理：为什么"按方法名"改游戏有效

> [!important] 一句话
> 这游戏是 **Godot 4 + C#（.NET 9）**。C# 的方法在内存里**带着名字**（元数据），
> 所以修改器可以「**说出方法名 → 问运行时要地址**」，而不用去记 `模块+0x1A2B3C` 这种死偏移。
> **这就是它跨版本还能用的原因。**

## 一、三条改法路线（层级从低到高）

| 路线 | 做什么 | 抗更新 | 本样本用了吗 |
|---|---|---|---|
| **① 改值** | 直接把某个字段/属性改成你要的数 | ★★（有些值有地址就够） | 用了（`Ctrl+Num 8 游戏速度` ≈ 写引擎时间缩放，无补丁模板） |
| **② 打补丁（AA 脚本）** | 在方法入口写 `jmp` 跳到自己的代码，改完再跳回 | ★★★★（按方法名取址） | ★ **主力**（17 处 `define` / 12 处 `alloc`） |
| **③ 挂事件（Harmony）** | 用 Harmony 给方法加 Prefix/Postfix，不碰机器码 | ★★★★★（最干净） | **没用**（但游戏目录自带 `0Harmony.dll` ⇒ 玩家侧可行 ✓） |

## 二、为什么"方法名 → 地址"这条路成立

```text
游戏启动
  └─ .NET 运行时加载 sts2.dll（8.93 MB 的托管程序集）
       └─ 元数据里保存：命名空间 / 类 / 方法名 / 签名
            └─ 方法第一次被调用时 JIT 编译成机器码 → 得到一个"代码地址"
                 └─ 这个「方法描述符 ↔ 机器码地址」的对应关系，运行时一直持有
                      └─ ClrMD / CE 的 Mono 接口能把它读出来
```

所以：

- **偏移会变**（每次编译/更新都可能变）✗
- **方法名基本不变**（`Creature::set_CurrentHp` 这种名字是写代码的人定的）✓

> [!tip] 反过来看原生游戏
> `01-Brotato`、`02-植物大战僵尸原版` 那种**原生 C++ / 无托管元数据**的游戏，没有"方法名字典"可用 ⇒
> 只能靠 **CE 找值 → 追指针 → AOB 特征码**，更新一次就得重找。这就是两类游戏在"改法"上的根本差别。

## 三、为什么"改这个方法"就有效（关键）

| 你改的东西 | 为什么游戏会认 |
|---|---|
| **属性的 setter**（`set_CurrentHp` / `set_Block` / `set_Gold`） | 游戏里**所有**改血/改盾/改钱的代码最终都走这个 setter ⇒ 在入口拦一道，等于"任何来源的改动都经过你" ✓ |
| **扣减方法**（`LoseEnergy` / `LoseStars`） | 能量/星星的唯一减少入口 ⇒ 让它"扣 0"就等于无限 ✓ |
| **Hook 的返回值**（`ModifyDamage` / `ModifyMerchantPrice` / `ModifyMaxEnergy`） | 游戏把这些数值**交给 Hook 算**，你改返回值 = 改结算结果 ✓ |
| **概率的 roll**（`PotionRewardOdds::Roll` / `CardRarityOdds::GetBaseOdds` / `UnknownMapPointOdds::Roll`） | 掉落/稀有度都从这个函数出结果 ⇒ 改成"必中" ✓ |
| **奖励上下限**（`EncounterModel::get_MinGoldReward` / `get_MaxGoldReward`） | 战斗结算的金币区间被改 ⇒ 金币倍率 ✓ |

> [!danger] 反面教材（我在别的游戏上真踩过）
> 在 `01-Brotato` 里我曾直接每帧回写"金币余额" ⇒ **无效甚至闪退** ✗。原因是那个游戏的余额由**信号驱动**、UI 会重新拉值。
> 正确做法是改**价格/结算函数**（也就是本节表格里的思路）✓
> **结论：改"真值的产生处"，不要改"显示出来的副本"。**

## 我是怎么做的（真实命令 + 真实输出）

```powershell
cd D:\sts2
python trainer_analyze.py    # PE 事实 + 导入表 + 宽字符串
python trainer_full.py       # 热键清单 + 游戏类型名
python trainer_scripts.py    # ★ 全部 AA 补丁模板（56 条）
```

决定性的真实输出（原样摘录）：


**从这些串我推出了什么**：既然出现 `//getmonomethod(类型::方法(签名))` 和 392 条 ClrMD 类型名，
说明它**靠 .NET 元数据拿地址**，而不是靠硬编码偏移 —— 这就是本篇"原理"一节的证据来源。

## 你该怎么做（零基础，三条路任选）

| 路 | 工具 | 操作 | 预期 |
|---|---|---|---|
| A | **ILSpy** | 打开 `sts2.dll` → 搜 `Creature` → 看 `CurrentHp` 属性 | 看到 setter 方法 |
| B | **CE** | 附加游戏 → `Mono` → `Dissect mono` → 找 `MegaCrit.Sts2.Core` → `Creature` | 看到字段偏移 + 方法是否带地址 |
| C | **ClrMD** | `DataTarget.AttachToProcess(pid)` → `ClrRuntime` → `ClrType.GetMethods()` | 程序集/类型/方法全列出来 |

## 四、怎么自己找出这些方法（三条路，按难度排）

| 路 | 工具 | 怎么做 | 适合谁 |
|---|---|---|---|
| **A** | **ILSpy / dnSpyEx** | 打开 `sts2.dll` → 搜类名（`Creature`/`Player`/`Hook`）→ 看属性 setter 与 Hook 方法 | ★ 最直观，零基础从这里开始 |
| **B** | **Cheat Engine → Mono → Dissect mono** | 附加游戏 → 列程序集 → 找类 → 看方法**是否带地址**（带 = 已 JIT） | 想边玩边验证 |
| **C** | **ClrMD（C# 库）** | `DataTarget.AttachToProcess` → `ClrRuntime` → 遍历 `ClrType.GetMethods()` → 拿 `ClrMethod.NativeCode` | 想自己写 Trainer |
