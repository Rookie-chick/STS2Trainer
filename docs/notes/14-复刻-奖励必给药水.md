# 14 · 功能 6：奖励必给药水

> [!important] 这一篇教第三种钩子：**强制返回**
> 前两个功能用了"帧钩子（轮询写字段）"和"setter 钩子（改参数）"。
> 奖励类功能大多是 `bool / int / enum` 的"算一下返回个决定"——
> 最省事也最安全的做法：**在入口直接 `mov eax,值; ret`**，连原方法体都不执行。
> 好处：不调任何托管方法 ⇒ 没有"异常穿过代码洞把进程搞死"的风险（对比 [[13-复刻-无限星星]] 的血案）。
> 热键：`Num 5`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 战斗结束后，奖励里**一定有药水** |
| 验收标准 | ① 打完一场，奖励面板出现"药水" ② 连打两场都有 ③ 关掉热键后恢复正常概率 |
| 热键 | `Num 5` |

## 2. 原理：药水是怎么"掷骰子"的

```csharp
// MegaCrit.Sts2.Core.Odds/PotionRewardOdds.cs
public bool Roll(Player player, AscensionManager ascensionManager, RoomType roomType)
{
    float currentValue = base.CurrentValue;                                     // 基础概率 0.4
    bool flag = Hook.ShouldForcePotionReward(player.RunState, player, roomType);
    float num  = ((roomType != RoomType.Elite) ? 0f : 0.25f);                    // 精英加成
    float num3 = currentValue + num * 0.5f;
    float num4 = _rng.NextFloat();
    if (flag || num4 < num3) { base.CurrentValue -= 0.1f; return true; }         // ← 给药水
    base.CurrentValue += 0.1f;  return false;                                   // ← 不给
}
```

| 做法 | 效果 | 风险 |
|---|---|---|
| 改 `CurrentValue` 字段 | 只是"概率高一点"（还有 pity 往回拉） | 不绝对 |
| **入口 `mov eax,1; ret`** | **恒返回 true = 必给** | 零（不执行原方法体） |

## 3. 我是怎么做的：怎么找出这个方法的（真实路径）

```text
① ILSpy 里 Ctrl+F 搜 "potion"（选 All）
   → 命中 MegaCrit.Sts2.Core.Odds.PotionRewardOdds
② 类里只有一个"掷骰子"方法：public bool Roll(Player, AscensionManager, RoomType)
   → 返回 bool ⇒ 典型"强制返回"目标
③ 搜 "Roll(" 的调用点 → 确认战斗结算时用它决定奖励里放不放药水
④ ClrMD 看有没有机器码
```

```powershell
dotnet run --project D:\sts2\clr\sts2clr -- <pid> methods MegaCrit.Sts2.Core.Odds.PotionRewardOdds Roll
```

**两种结果都要会处理**：

```text
A. native=0x7FF7xxxxxxxx              → 直接挂
B. native=0xFFFFFFFFFFFFFFFF          → 还没 JIT（要等第一次算奖励）
   ⇒ 延迟安装：主循环每 2 秒重查一次，一拿到地址立刻挂上（第一次奖励赶不上，第二次起生效）
```

> [!warning] 为什么会是 B
> .NET 是"用到才编译"。`Roll` 只有"战斗结束算奖励"那一刻才第一次被调用，
> 战斗中途装它时它可能压根还没有机器码。这就是"延迟安装"存在的原因。

## 4. 你该怎么做：代码怎么写

### 4.1 钩子本体

```csharp
public static byte[] InstallForceReturnHook(IntPtr h, ulong methodAddr, ulong flagAddr, int retValue)
{
    var head = Read(h, methodAddr, 16);
    int n = PrologueLen(head);                        // 覆盖 ≥5 字节的整指令长度
    var original = new byte[n]; Array.Copy(head, 0, original, 0, n);
    ulong cave = AllocNear(h, methodAddr, 0x1000);    // E9 只能跳 ±2GB

    var c = new List<byte>();
    B(0x50);                                  // push rax
    B(0x48, 0xB8); I64(flagAddr);             // mov rax,&开关
    B(0x83, 0x38, 0x00);                      // cmp dword [rax],0
    int jeAt = c.Count; B(0x74, 0x00);        // je  原样
    B(0x58);                                  // pop rax
    B(0xB8); I32(retValue);                   // mov eax,返回值
    B(0xC3);                                  // ret        ← 直接返回
    int origAt = c.Count;
    c[jeAt + 1] = (byte)(origAt - (jeAt + 2));
    foreach (var b in original) B(b);         // 原样路径
    B(0xE9); I32(back);                       // jmp 回 方法+n

    WriteProcessMemory(h, cave, code);
    Patch(h, methodAddr, cave, n);            // 入口改 E9 + nop…
    return original;                          // 退出时还原用
}
```

生成的机器码：

```asm
50                 push rax
48 B8 <&flag>      mov  rax,&开关
83 38 00           cmp  dword [rax],0
74 07              je   原样
58                 pop  rax
B8 01 00 00 00     mov  eax,1        ; true
C3                 ret
原样: <原 n 字节> ; E9 跳回
```

### 4.2 接入 Trainer（三处）

```csharp
// ① Game.cs
public const string T_POTIONODDS = "MegaCrit.Sts2.Core.Odds.PotionRewardOdds";
public ulong FnPotionRoll = Method(T_POTIONODDS, "Roll");      // 可能是 0（未 JIT）

// ② Program.cs：先试一次
var potionOrig = g.FnPotionRoll >= 0x10000
    ? Hook.InstallForceReturnHook(h, g.FnPotionRoll, F(5), 1) : null;

// 主循环里每 2 秒重试（等它被第一次 JIT）
if (potionOrig == null && TickCount64() - lastTry > 2000)
{
    lastTry = TickCount64();
    ulong addr = g.Method(Game.T_POTIONODDS, "Roll");
    if (addr >= 0x10000)
    {
        potionOrig = Hook.InstallForceReturnHook(h, addr, F(5), 1);
        Hook.WriteI32(h, F(5), state[5] ? 1 : 0);
        Console.WriteLine("  ✓ 延迟安装成功：奖励必给药水（下一场起）");
    }
}

// ③ 热键 + 退出还原
(VK_NUMPAD5, false);
Hook.Restore(h, g.FnPotionRoll, potionOrig);
```

## 5. 怎么验证（四步）

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | 打完一场（或任何触发结算的场景） | 控制台出现 `✓ 延迟安装成功` |
| 2 | 再 `methods … PotionRewardOdds Roll` | `native=0x7FF7…`（不再是 0xFFFF） |
| 3 | 再打一场看奖励面板 | **一定**有药水（连打 3 场都有） |
| 4 | 按 `Num 5` 关掉再打 | 恢复概率（可能没有药水） |

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 方法还没 JIT | `native=0xFFFF…` | 延迟安装（4.2 第②段） |
| 把 `0xFFFF…` 当地址 | 游戏**直接崩** | 任何 `call`/`patch` 前先判 `>=0x10000 && != ulong.MaxValue` |
| 装了不生效 | 你装的时候奖励已算完 | 奖励是一次性结算，只对"下一次"生效 |
| 一开就崩 | 顺手调了 `ShouldForcePotionReward` 之类 | 回归"只返回"的最简写法 |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| `PotionRewardOdds.Roll(Player, AscensionManager, RoomType)` 返回 bool，是"给不给药水"的唯一决定点 | 反编译源码，类里只有这一个掷骰方法 |
| 本机这局里 `Roll` 未 JIT（0xFFFF…） | `methods` 命令输出 |
| "强制返回"模板可生成、入口可校验 | 同款模板已在其它钩子上跑通 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| 改 `CurrentValue` 能"必给" | 有 pity/上限，只是提高概率 |
| 未 JIT 也能装 | 没地址，`PrologueLen` 直接失败 |

### ⏳ 待验证（需打完一场）

| 结论 | 怎么验 |
|---|---|
| 装上后奖励 100% 有药水 | 打 3 场，每次都看奖励面板 |
| 关掉恢复概率 | `Num 5` 关掉再打 |
| 连打不崩 | 打 5 场以上 |
