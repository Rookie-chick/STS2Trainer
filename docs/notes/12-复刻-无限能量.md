# 12 · 功能 4：无限能量（零基础手把手）

> [!important] 这篇的核心是**一个判断**：类里有一堆 `XxxChanged` 回调，但**改文字的不一定是它**
> 能量只有 3 个相关方法：`OnEnergyChanged`（事件回调，只放特效）、`RefreshLabel`（真正 `SetTextAutoSize`）、`_Process`（只转圈）。
> 调错了 = 白忙。所以第 3 节教你**怎么在反编译里一眼认出哪个是刷新方法**。
> 热键：`Num 3`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 能量永远满，出牌不消耗；左下能量球数字同步 |
| 验收标准 | ① 能量球显示 `4/4` ② 外部把 `_energy` 写成 0，600ms 内回 4 ③ 与其它功能同时生效 |
| 热键 | `Num 3`（锁定值 = 启动时读到/命令行指定，默认取"界面上的上限"） |

## 2. 原理

```csharp
// ① 数据：PlayerCombatState.cs:90
public int Energy { get => _energy; private set { if (_energy != value) { ... EnergyChanged?.Invoke(old,new); } } }

// ② 扣能量入口：PlayerCombatState.cs:178
public void LoseEnergy(decimal amount) { if (amount < 0m) throw ...; Energy = (int)Math.Clamp((decimal)Energy - amount, 0m, 999999999m); }

// ③ 事件回调（★它不刷数字！）：NEnergyCounter.cs:235
private void OnEnergyChanged(int oldEnergy, int newEnergy)
{ if (oldEnergy < newEnergy) { _backVfx?.Restart(); _frontVfx?.Restart(); } }

// ④ 真正刷数字的：NEnergyCounter.cs:217
private void RefreshLabel()
{
    var pcs = _player.PlayerCombatState;
    _label.SetTextAutoSize($"{pcs.Energy}/{pcs.MaxEnergy}");   // ← 读实时字段
    ...
}

// ⑤ 每帧只转圈，不刷数字：NEnergyCounter.cs:244
public override void _Process(double delta) { float num = (Energy == 0) ? 5f : 30f; ...RotationDegrees += ... }

// ⑥ 上限是算出来的，不是字段！
public int MaxEnergy => (int)Hook.ModifyMaxEnergy(_player.Creature.CombatState, _player, _player.MaxEnergy);
```

### 2.1 怎么一眼认出"哪个方法才刷文字"

在 ILSpy 里打开这个类，按 `Ctrl+F` 搜 **`SetTextAutoSize`** 或 **`Text =`**：

- 命中的那个方法 = 真正改文字的方法（这里是 `RefreshLabel`）
- 只在 `if (oldEnergy < newEnergy)` 里放特效的 = 没用，别调
- 记住：**"名字里带 Changed" 不等于 "刷新 UI"**

### 2.2 上限是算出来的：锁值该填多少

| 来源 | 值 |
|---|---|
| 字段 `Player.MaxEnergy`（ClrMD 0xE8 → 真实 0xF0） | **3** |
| 界面上显示的 `x/4` | **4**（有遗物通过 `Hook.ModifyMaxEnergy` 加了 1） |

所以锁值要用"界面上的上限"。本项目默认 `max(4, 当前能量)`，也可以用命令行第 2 个参数指定。

## 4. 你该怎么做（在 Trainer 里加"能量锁"）

### 4.1 登记（`Game.cs`）

```csharp
public const int OFF_PCS_ENERGY = 0x68;   // PlayerCombatState._energy（ClrMD 0x60 + 8）
public const int OFF_PLAYER_PCS = 0x98;   // Player.<PlayerCombatState>（ClrMD 0x90 + 8）
public const int OFF_COUNTER_PLAYER = 0x20; // NEnergyCounter._player（ClrMD 0x18 + 8）

// Resolve() 里：
Pcs = (ulong)ReadI64(Player + OFF_PLAYER_PCS);
EnergyUi = FindNodeOwnedBy(T_ENERGY, OFF_COUNTER_PLAYER, OFF_COUNTER_PLAYER);
FnRefreshLabel = Method(T_ENERGY, "RefreshLabel");
```

### 4.2 加一条 Action（`Program.cs`）

```csharp
new Hook.Action{
    Name      = "无限能量",
    FlagAddr  = F(2),                       // Num 3 → 开关
    CheckAddr = g.Pcs + Game.OFF_PCS_ENERGY,
    Target    = energyLock,                 // 锁定值（界面上限）
    WriteAddr = g.Pcs + Game.OFF_PCS_ENERGY,
    CallThis  = g.EnergyUi,                 // NEnergyCounter 实例
    CallFn    = g.FnRefreshLabel,           // ★RefreshLabel，不是 OnEnergyChanged
},
```

### 4.3 热键

```csharp
(VK_NUMPAD3, false),   // Num 3
```

## 5. 验证

| 步骤 | 命令/操作 | 期望 |
|---|---|---|
| 字段 | Trainer 打印 `Combat = ... energy=4` | 与画面一致 |
| 画面 | 截图左下能量球 | `4/4` |
| 强写 | `pokeenergy 0` | 600ms 后回 4 |
| 开关 | `Num 3` | `[关] 无限能量`；此时强写不会被补回 |

## 6. 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 开了功能但数字不动 | 调了 `OnEnergyChanged`（它只放特效） | 换成 `RefreshLabel` |
| 显示 `3/4` 很怪 | 锁值取了字段 `Player.MaxEnergy`（=3） | 用界面上的上限（4） |
| 一开就崩 | 调的刷新方法内部抛异常 | 见 [[13-复刻-无限星星]] 的排查与替代法 |
| `RefreshLabel=0` | 没 JIT | 进战斗打一张牌后再装 |

## 7. 回滚

按 `Q` 还原补丁；强杀则重启游戏。

## 8. 三类结论

### ✅ 已验证

| 结论 | 证据 |
|---|---|
| `_energy` 真实偏移 **0x68** | 字段 dump + 锁值后界面同步 |
| 刷数字的是 `RefreshLabel`，不是 `OnEnergyChanged` | 反编译 `NEnergyCounter.cs:217 / 235` |
| 锁字段 + 调 `RefreshLabel` 能上屏 | 能量球 `4/4` |
| 强写 0 会 600ms 内回满 | `pokeenergy 0` |
| 上限是算出来的 | 字段 3 / 界面 4 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| 调 `OnEnergyChanged` 能刷数字 | 只放粒子特效，文字不动 |
| 用字段 `Player.MaxEnergy` 当锁值 | 显示 `3/4`，很怪 |

### ⏳ 待验证

| 结论 | 怎么验 |
|---|---|
| 真打出一张牌时能量不掉 | 拖拽出牌的自动化在这台机器上没打通，需人工打一张 |
