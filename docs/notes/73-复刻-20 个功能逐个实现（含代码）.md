# 73 · 复刻：20 个功能逐个实现

> [!info] 这篇怎么用
> 每个功能都给四样：**① 改哪个方法 ② 为什么有效 ③ 代码（CE AutoAssembler） ④ 怎么验证**。
> 方法名全部来自样本 `70` 篇的实测（✅ 已验证）；**代码是按 AA 语法手写的模板**（✅ 语法来自样本，⚠ 未在本机游戏上跑过 —— 标 ⏳ 的地方就是要你亲手验证的）。

## 二、A 类：资源类（无限血 / 盾 / 能量 / 星星）

### 为什么有效
游戏改血量**唯一**经过 `Creature::set_CurrentHp`（属性 setter）。在它入口跳走 → 你先看"要写多少" → 想写小就改成最大值 → 再跳回让原逻辑执行。**所有伤害来源都被这一处拦住** ✓

### 代码 1：AA 脚本（无限血）

```text
[ENABLE]
// ===== 1) 按方法全名取址（这就是"怎么找到地址"的答案：不找偏移，问运行时） =====
define(address,MegaCrit.Sts2.Core.Entities.Creatures.Creature::set_CurrentHp)
label(code)
label(return)
label(health)              // 把"当前血量该是多少"暴露成符号，UI 侧读它
registersymbol(health)

alloc(newmem,$1000,MegaCrit.Sts2.Core.Entities.Creatures.Creature::set_CurrentHp)

newmem:
  // 进入 setter 时：rcx = this(Creature*)，rdx = 新血量
  // 这里演示"开关打开就把新血量改成最大值"
  cmp dword ptr [inf_hp_on], 0
  je code
  mov rdx, [rcx + HP_MAX_OFFSET]   // ← 上限字段偏移，见下方"怎么找这个偏移"
  mov [rcx + HP_CUR_OFFSET], rdx   // 顺手把当前值也写成上限（防回弹）
code:
  // 补回被 jmp 覆盖的原指令（用 CE 打开方法头，看前几字节是什么就补什么）
  mov [rcx + HP_CUR_OFFSET], rdx
  jmp return

MegaCrit.Sts2.Core.Entities.Creatures.Creature::set_CurrentHp:
  jmp newmem
  nop

return:

[DISABLE]
MegaCrit.Sts2.Core.Entities.Creatures.Creature::set_CurrentHp:
  db 48 89 91 ?? ?? ?? ??      // ← 原字节，用 CE 的"恢复原始代码"自动填
dealloc(newmem)
unregistersymbol(health)
```

> [!warning] 两个 ⏳ 需要你实测的点
> 1. **`HP_MAX_OFFSET` / `HP_CUR_OFFSET`** 是字段偏移 —— 用 CE 的 `Dissect mono` 打开 `Creature` 类，能看到字段名与偏移（`_currentHp` / `_maxHp` 之类）
> 2. **方法头原字节** —— CE 里选中方法地址 → 右键 `Disassemble` → 看前 5~8 字节；AA 的 `[DISABLE]` 段要原样写回
> 这两步没做，脚本只会崩游戏，不会生效 ✗

### 代码 2：扣减类（无限能量 / 无限星星）——比 setter 更简单

```text
[ENABLE]
define(address,MegaCrit.Sts2.Core.Entities.Players.PlayerCombatState::LoseEnergy)
label(return)
alloc(newmem,$1000,MegaCrit.Sts2.Core.Entities.Players.PlayerCombatState::LoseEnergy)
newmem:
  ret                      // 直接返回 = 永远不扣
MegaCrit.Sts2.Core.Entities.Players.PlayerCombatState::LoseEnergy:
  jmp newmem
  nop
return:
[DISABLE]
MegaCrit.Sts2.Core.Entities.Players.PlayerCombatState::LoseEnergy:
  db <原字节>
dealloc(newmem)
```
星星同理：`…PlayerCombatState::LoseStars`。

> [!tip] 为什么"扣减函数直接 ret"比"改上限"更稳
> 因为它是**唯一入口**且**无副作用**（扣 0 就是了）。而 setter 改值要处理"上限/回弹/每帧重设"，坑更多。

## 三、B 类：概率类（药水 / 卡牌升级 / 稀有度 / 未知点）

### 为什么有效
掉落与稀有度都由 **Odds 类**的 `Roll()` / `GetBaseOdds()` 出结果。这类方法返回值通常是"是否成功"或"权重"，**你把返回值改掉，游戏后续逻辑就按你给的结果走** ✓

### 代码 3：必给药水（`PotionRewardOdds::Roll`）

```text
[ENABLE]
define(address,MegaCrit.Sts2.Core.Odds.PotionRewardOdds::Roll)
label(return)
alloc(newmem,$1000,MegaCrit.Sts2.Core.Odds.PotionRewardOdds::Roll)
newmem:
  mov al, 1               // 强制 true（返回值在 al/rax）
  ret
MegaCrit.Sts2.Core.Odds.PotionRewardOdds::Roll:
  jmp newmem
  nop
return:
[DISABLE]
MegaCrit.Sts2.Core.Odds.PotionRewardOdds::Roll:
  db <原字节>
dealloc(newmem)
```

> ⏳ **待验证**：`Roll` 的返回类型（bool？还是某个枚举/结构？）—— 用 ILSpy 打开 `sts2.dll` 看 `PotionRewardOdds.Roll()` 的签名再决定是 `mov al,1` 还是改结构体字段。**这就是"为什么必须先看签名"的原因。**

## 四、C / D / E / F 类（速查代码骨架）

### C-1 改金币（`Player::set_Gold(Int32)`）

```text
[ENABLE]
define(address,MegaCrit.Sts2.Core.Entities.Players.Player::set_Gold(Int32))
label(return)
alloc(newmem,$1000,MegaCrit.Sts2.Core.Entities.Players.Player::set_Gold(Int32))
newmem:
  mov edx, #999999        // 忽略游戏传来的值，永远写 999999
  jmp return
MegaCrit.Sts2.Core.Entities.Players.Player::set_Gold(Int32):
  jmp newmem
  nop
return:
```
（样本里这条的 label 是 `edit_gold`，并且它是**先用 `aobscanregion` 在 `NEnergyCounter::_Process` 里定位 `PlayerCombatState` 字段**，再写值 —— 说明作者也遇到过"setter 被内联/多态调用"的情况 ⇒ 这时用特征码兜底。）

### C-2 金币倍率（`EncounterModel::get_MinGoldReward` / `get_MaxGoldReward`）

```text
[ENABLE]
define(address,MegaCrit.Sts2.Core.Models.EncounterModel::get_MinGoldReward)
alloc(newmem,$1000,MegaCrit.Sts2.Core.Models.EncounterModel::get_MinGoldReward)
label(goldmul_f) registersymbol(goldmul_f)   // 放一个 float 当倍率，UI 可调
newmem:
  cvtsi2ss xmm0, eax        // 原返回值 int → float（按实际返回类型调整）
  mulss xmm0, [goldmul_f]
  cvttss2si eax, xmm0
  ret
MegaCrit.Sts2.Core.Models.EncounterModel::get_MinGoldReward:
  jmp newmem
  nop
```
`get_MaxGoldReward` 同样处理（样本里这两条都挂了 ✓）。

### D 伤害/防御倍率（`Hook::ModifyDamage`）

注意：样本里对 **两个不同签名** 都下了补丁：
```text
…Hook::ModifyDamage(…, MegaCrit.Sts2.Core.Combat.ICombatState, …)
…Hook::ModifyDamage(…, MegaCrit.Sts2.Core.Combat.CombatState,  …)
```
⇒ **接口版与实现版各有一处**，只挂一处会出现"某些情况下失效" ✗ ⇒ 两处都挂 ✓

```text
[ENABLE]
define(address,MegaCrit.Sts2.Core.Hooks.Hook::ModifyDamage(MegaCrit.Sts2.Core.Runs.IRunState,MegaCrit.Sts2.Core.Combat.ICombatState,MegaCrit.Sts2.Core.Entities.Creatures.Creature,MegaCrit.Sts2.Core.Entities.Creatures.Creature, …))
label(dmg) label(dmgmul_f) label(defmul_f)
registersymbol(dmg dmgmul_f defmul_f)
alloc(newmem,$1000,address)
newmem:
  // 返回值是"最终伤害"；先补原指令，再乘倍率
  // ⏳ 具体寄存器/浮点位置要按 ModifyDamage 的返回类型（int? float?）用 ILSpy 确认
  jmp return
address:
  jmp newmem
  nop
return:
```

## 五、通用骨架：从零做一个功能的标准 6 步

```text
① 想清楚"这件事由哪个方法决定"       → ILSpy 搜类名/方法名（Creature / Player / Hook / Odds…）
② 确认它是否已 JIT（有机器码）        → CE → Mono → Dissect mono → 看方法是否带地址
③ 看方法头原字节 + 调用约定           → CE 里 Disassemble，记住 rcx/rdx/xmm0 是什么
④ 写 AA 脚本（define/alloc/label/jmp）→ 见上面的模板
⑤ 打开功能 → 在游戏里**看画面/数值** → 这是唯一判据（不是"脚本没报错"）
⑥ 记录：方法名 / 偏移 / 原字节 / 版本号 → 写进本子库（下次更新照样能重做）
```

## 七、C# 路线（更干净，但加载方式 ⏳ 待验证）

游戏目录**自带 `0Harmony.dll`** ⇒ 理论上可以写 Harmony 补丁，不用碰机器码：

```csharp
using HarmonyLib;

[HarmonyPatch(typeof(MegaCrit.Sts2.Core.Hooks.Hook), nameof(MegaCrit.Sts2.Core.Hooks.Hook.ModifyMerchantPrice))]
public static class FreeShopPatch
{
    // Postfix：拿到原结果后改成 0
    public static void Postfix(ref int __result) => __result = 0;
}

// 无限血：拦属性 setter
[HarmonyPatch(typeof(MegaCrit.Sts2.Core.Entities.Creatures.Creature), "set_CurrentHp")]
public static class InfiniteHpPatch
{
    public static void Prefix(MegaCrit.Sts2.Core.Entities.Creatures.Creature __instance,
                              ref int value)
    {
        value = __instance.MaxHp;   // 永远写满（字段名以 ILSpy 实际为准）
    }
}

// 入口
var harmony = new Harmony("yg.sts2.trainer");
harmony.PatchAll();
```

> [!warning] ⏳ 唯一没验证的一环：**怎么把这段 C# 塞进这个 Godot 游戏**
> 候选方案（按可能性排）：
> 1. 把编译出的 dll 放到游戏程序集目录，靠 Godot 的装配加载（需要看它是否自动扫描）
> 2. 用 Godot 的 `--script` / `[Tool]` 脚本机制做宿主
> 3. 用注入器把 dll 加载进 `SlayTheSpire2.exe`，再 `harmony.PatchAll()`
> **验证方法**：先用方案 3 在虚拟机里试，`Process Monitor` 看 dll 是否被加载；能加载就成功一半。
