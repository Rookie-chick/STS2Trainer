# 20 · 功能 12：伤害倍率（×N）

> [!important] 19 篇是"把数值改成固定值"，这一篇是"把数值乘 N"
> 技术上多一步：**读 decimal → 乘 → 写回**。
> 只要数值是整数（`mid=hi=0`、`scale=0`），乘 `lo` 就够了——这是 90% 的伤害/金币场景。
> 真要处理小数（比如 ×1.5），就得调 `System.Decimal.op_Multiply`（本篇章末讲思路）。
> 热键：`Num .`（小键盘小数点）

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 你造成的伤害 ×N（N 可配，默认 10） |
| 验收标准 | ① 打 6 点伤害的牌实际掉 60 ② 敌人打你**不**翻倍 ③ 关掉恢复 |
| 热键 | `Num .` |

## 2. 原理

```csharp
// 19 篇的同一层：Creature.LoseHpInternal(decimal amount, ValueProp props)
// rcx = this(受伤者)   rdx = &amount(decimal)   r8d = props
CurrentHp = Math.Max(CurrentHp - num, 0);
```

差别只在代码洞里做什么：

| 篇 | 代码洞里干的事 |
|---|---|
| 19（超级伤害） | `[rdx] = 9999`（覆盖） |
| **20（倍率）** | `eax = [rdx] * N; [rdx] = eax`（读-乘-写） |

### 2.1 为什么可以先只乘 `lo`

```text
decimal 的"整数值"一定满足：mid = 0, hi = 0, flags(scale) = 0
  6     → lo=6,    mid=0, hi=0, flags=0
  9999  → lo=9999, mid=0, hi=0, flags=0
⇒ 乘一个整数 N，结果仍然只需要 lo 部分（只要不溢出 2^31）
```

> 如果伤害可能是小数（例如 2.5），`lo` 里存的是 **25**，`scale=1`。
> 这时直接 `lo*10` 得到 250 —— 而 scale 还是 1 ⇒ 实际值 25.0，等于没变。
> 这种情况下要么把 scale 也改掉，要么走"调 op_Multiply"的正规路（见第 6 节）。

## 4. 你该怎么做：代码怎么写

### 4.1 机器码：读-乘-写

```asm
; 门禁：功能开关 + 只改敌人（rcx != 玩家Creature）
8B 02                 mov  eax,[rdx]        ; eax = amount.lo
69 C0 0A 00 00 00     imul eax,eax,10       ; eax *= 10        （N 放这里）
89 02                 mov  [rdx],eax        ; 写回 lo
C7 42 04 00 00 00 00  mov  dword [rdx+4],0  ; mid  = 0
C7 42 08 00 00 00 00  mov  dword [rdx+8],0  ; hi   = 0
C7 42 0C 00 00 00 00  mov  dword [rdx+0xC],0; flags= 0（scale=0，整数）
```

> `imul eax,eax,imm32` 是 `69 C0 imm32`（6 字节），N 直接写在指令里 ⇒ 改倍率只要重建代码洞。

### 4.2 钩子（在 19 篇的 `InstallDecimalArgHook` 上改 4 条指令）

```csharp
// 只要把 19 篇里"写 9999"那 4 条，换成"读-乘-写"
B(0x8B, 0x02);                              // mov eax,[rdx]
B(0x69, 0xC0); I32(multiplier);             // imul eax,eax,N
B(0x89, 0x02);                              // mov [rdx],eax
B(0xC7, 0x42, 0x04); I32(0);                // mov dword [rdx+4],0
B(0xC7, 0x42, 0x08); I32(0);                // mov dword [rdx+8],0
B(0xC7, 0x42, 0x0C); I32(0);                // mov dword [rdx+0xC],0
```

> [!danger] 三条命门（和 19 篇一样）
> 1. `push rax` / `pop rax`（我们用了 eax）
> 2. 16 字节都要处理（mid/hi/flags 清零，否则数值爆炸）
> 3. **必须门禁**：`cmp rcx, 玩家Creature` → 相等就跳过（否则敌人打你也翻倍）

### 4.3 接入 Trainer

```csharp
// 和 19 篇共用同一个挂点，只是"开哪个"由开关决定
// 方案 A：两个功能二选一（推荐，避免互相打架）
//   F(10) = 超级伤害（写 9999）   F(11) = 伤害倍率（×N）
// 方案 B：一个动作里先判断要覆盖还是要乘（代码洞稍长，但可以共存）

var dmgMulOrig = g.FnLoseHp >= 0x10000
    ? Hook.InstallDecimalMulHook(h, g.FnLoseHp, F(11), g.Creature, 10) : null;
// keys 加 (VK_DECIMAL, false) → Num .
// names 加 "伤害倍率 x10"
```

## 6. 进阶：真的要处理小数倍率（比如 ×1.5）

```text
思路：不自己算，直接调 .NET 的 decimal 乘法
  ① 用 ClrMD 找到 System.Decimal.op_Multiply(decimal, decimal) 的地址
  ② 代码洞里：准备两个 decimal（原值 + 倍率），按 x64 调用约定调它
     decimal 返回走隐藏指针 ⇒ 还要先给结果留 16 字节缓冲、把指针放 rcx
  ③ 把结果写回 [rdx]
这条路的坑：需要一块可写的 16 字节缓冲（可以用我们 AllocFlags 那块内存的尾部）+
             必须保存所有会被污染的寄存器。
⇒ 新手建议：先用"整数倍"（本篇），等熟练了再上小数倍。
```

## 7. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 乘完变成天文数字 | mid/hi/flags 残留 | 16 字节全部重写 |
| ×1.5 没效果 | scale 没动（见 2.1） | 用整数倍，或走 op_Multiply |
| 自己也翻倍 | 门禁漏了 | `cmp rcx,玩家Creature` + `je 原样` |
| 溢出成负数 | 伤害太大（×N 后超过 int32） | N 调小，或先判断 `cmp eax,100000` 再乘 |

## 8. 三类结论

### ✅ 已验证（机制层面）

| 结论 | 证据 |
|---|---|
| `LoseHpInternal` 的 `amount` 在 `rdx` 指向的 16 字节里 | 19 篇的 ABI 分析 |
| 整数 decimal 的 `mid/hi/flags` 全 0，只需改 lo | decimal 布局 |
| `imul eax,eax,imm32` 可直接做整数倍 | x86-64 指令表 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| 只改 lo 就能实现小数倍率 | scale 不变 ⇒ 实际值不变 |
