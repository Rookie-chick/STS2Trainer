# 17 · 功能 9：地图上的 `?` 点必出宝箱

> [!important] 这一篇的关键动作：**先查清枚举的数值**
> 返回值是 `RoomType`（本质 int）。要它返回"宝箱"，就得知道 `Treasure` 是第几个。
> **枚举值不是猜的，是数出来的**——这就是第 2 节要做的事。
> 热键：`Num 8`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 地图上所有 `?`（Unknown）点，进去必是宝箱房 |
| 验收标准 | ① 走一个 `?` 点是宝箱 ② 连走 3 个都是 ③ 关掉恢复 |
| 热键 | `Num 8` |

## 2. 原理（含"数枚举"）

```csharp
// MegaCrit.Sts2.Core.Odds/UnknownMapPointOdds.cs
public const float baseMonsterOdds  = 0.1f;
public const float baseEliteOdds    = -1f;
public const float baseTreasureOdds = 0.02f;
public const float baseShopOdds     = 0.03f;

public RoomType Roll(IEnumerable<RoomType> blacklist, IRunState runState)   // ← 返回房间类型
{ /* 按概率掷骰，返回 Monster / Treasure / Event … */ }
```

```csharp
// MegaCrit.Sts2.Core.Rooms/RoomType.cs  ← ★数出来的顺序
Monster,   // 0
Elite,     // 1
Boss,      // 2
Treasure,  // 3   ← 让它返回 3
Shop,      // 4
Event,     // 5
RestSite,  // 6
```

> [!tip] 怎么自己确认枚举值（三种办法）
> 1. **读源码按顺序数**（没有显式赋值就是从 0 递增）
> 2. 看有没有显式赋值：`Treasure = 3` 就直接读
> 3. 运行时验证：在游戏里真的进几次 `?` 点，用 `raw` 读返回值的实际玩家侧记录（进阶）

## 4. 你该怎么做：代码怎么写

### 4.1 enum 返回（= int，走 eax）

```asm
B8 03 00 00 00        mov eax,3        ; RoomType.Treasure
C3                    ret
```

### 4.2 钩子（直接复用 14 篇的 bool 版本）

```csharp
// bool 和 enum 都从 eax 返回，同一个模板
var mapOrig = Hook.InstallForceReturnHook(h, g.FnUnknownRoll, F(8), 3);   // 3 = Treasure
```

> [!tip] 为什么不用新写一个
> `enum` 在 ABI 上是 4 字节 int，JIT 把它放 `eax`；`bool` 也会被规整成 0/1 放 `eax`。
> 所以 `mov eax,值; ret` 对 bool / int / enum **全通用**。

### 4.3 接入 Trainer

```csharp
// Game.cs
public const string T_UNKNOWNODDS = "MegaCrit.Sts2.Core.Odds.UnknownMapPointOdds";
public ulong FnUnknownRoll = Method(T_UNKNOWNODDS, "Roll");

// Program.cs
var mapOrig = g.FnUnknownRoll >= 0x10000
    ? Hook.InstallForceReturnHook(h, g.FnUnknownRoll, F(8), 3) : null;   // 未 JIT 就延迟安装
// keys 加 (VK_NUMPAD8, false) → Num 8；names 加 "未知点必宝箱"
```

## 5. 怎么验证

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | `methods … UnknownMapPointOdds Roll` | 有地址（没有就先随便进一个 `?` 点） |
| 2 | 装完 `raw <入口> 16` | 前 5 字节 `E9 …` |
| 3 | 地图上走进一个 `?` 点 | 直接进宝箱房 |
| 4 | 连走 3 个 `?` | 每次都是宝箱 |
| 5 | `Num 8` 关掉再走一个 | 恢复怪物/事件/商店 |

> [!warning] 别和"地图上本来就有的宝箱点"搞混
> `MapPointType.Treasure` 是地图上画出来的宝箱；这个功能只影响 **`?`（Unknown）** 解析出来的房间类型。

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 枚举数错 | 返回了别的房间（比如 Shop） | 按第 2 节三种办法重新确认 |
| 类还没实例 | `types` 搜不到 | 延迟安装（方法地址不依赖实例） |
| 装了没反应 | 装的时候这个 `?` 已解析完 | 只对"下一次进点"生效 |
| 被黑名单过滤 | 某些位置不允许宝箱 | `blacklist` 主要拦"连续两个宝箱"，一般无碍 |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| `?` 点房间类型由 `UnknownMapPointOdds.Roll(blacklist, runState)` 返回 | 反编译：返回 `RoomType` |
| `RoomType.Treasure` = **3** | 源码按顺序数：Monster0/Elite1/Boss2/Treasure3 |
| enum 与 bool 同走 `eax`，可复用同一模板 | x64 ABI + JIT 约定 |
