# 24 · 功能 16：编辑最大能量

> [!important] 这一篇把 12 篇的一个坑讲透：**"上限"是算出来的，不是字段**
> 12 篇里我们看到 `MaxEnergy => Hook.ModifyMaxEnergy(...)`；
> 这次直接把这个"算"的地方改掉：让 `ModifyMaxEnergy` 返回你想要的数。
> 热键：`Ctrl+Num 4`

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 每回合的最大能量变成 N（默认 10） |
| 验收标准 | ① 回合开始时能量球显示 `10/10` ② 打牌后仍按 10 结算 ③ 关掉恢复 |
| 热键 | `Ctrl+Num 4` |

## 2. 原理

```csharp
// MegaCrit.Sts2.Core.Entities.Players/PlayerCombatState.cs
public int MaxEnergy => (int)Hook.ModifyMaxEnergy(_player.Creature.CombatState, _player, _player.MaxEnergy);
//                     ↑ 每次问"最大能量"都现算 ⇒ 改 ModifyMaxEnergy 的返回值即可

// MegaCrit.Sts2.Core.Hooks/Hook.cs
public static decimal ModifyMaxEnergy(ICombatState combatState, Player player, decimal amount)
{
    decimal num = amount;
    foreach (AbstractModel item in IterateCombatHookListeners(combatState))
        num = item.ModifyMaxEnergy(player, num);       // 遗物可以 +1 能量
    return num;                                         // ← 最终上限
}
```

⇒ 让 `ModifyMaxEnergy` 返回 **10**，最大能量就是 10。

> [!tip] 为什么改这里而不是改 `Player.MaxEnergy` 字段
> 字段是"角色基础值"（比如 3），而游戏真正用的是 `PlayerCombatState.MaxEnergy`（算出来的）。
> 改字段只能影响"没被遗物改过"的情况；改 `ModifyMaxEnergy` 才是**最终生效值**。

## 3. 我是怎么做的：怎么找出这个方法的（真实路径）

```text
② ILSpy 搜 "ModifyMaxEnergy" → 命中 Hook.ModifyMaxEnergy(ICombatState, Player, decimal)
③ 返回 decimal ⇒ 用 15 篇的 decimal 返回钩子，值填 10
④ ClrMD 确认地址（战斗中已 JIT）
```

## 4. 你该怎么做：代码怎么写

```csharp
// Game.cs
public ulong FnMaxEnergy = Method("MegaCrit.Sts2.Core.Hooks.Hook", "ModifyMaxEnergy");

// Program.cs
var maxEnergyOrig = g.FnMaxEnergy >= 0x10000
    ? Hook.InstallForceDecimalReturnHook(h, g.FnMaxEnergy, F(14), 10m) : null;
// keys 加 (VK_NUMPAD4, ctrl:true) → Ctrl+Num 4；names 加 "最大能量=10"
```

生成的机器码（decimal 10 = lo=10, 其余 0）：

```asm
C7 01 0A 00 00 00        mov dword [rcx],10       ; lo = 10
C7 41 04 00 00 00 00     mov dword [rcx+4],0
C7 41 08 00 00 00 00     mov dword [rcx+8],0
C7 41 0C 00 00 00 00     mov dword [rcx+0xC],0    ; flags=0 → 10
48 89 C8                 mov rax,rcx
C3                       ret
```

> [!tip] 和 12 篇（无限能量）配合
> 12 篇把"当前能量"锁死；24 篇把"上限"提高。两个一起开 = 每回合 10 点且用不完。
> 但注意：12 篇的锁值是"启动时读到的上限"，改了上限后要**重开一次 12 篇的锁**才会跟着变。

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 改 `Player.MaxEnergy` 字段没效果 | 界面还是 3/4 | 改 `Hook.ModifyMaxEnergy`（本篇） |
| 显示 10 但只能打 3 费 | 12 篇的能量锁还锁在旧值 | 关掉再开一次 12 篇的锁 |
| 一开就崩 | 用了错误的返回寄存器（decimal 写成 eax） | 用 15 篇的 decimal 模板 |
| 未 JIT | 0xFFFF | 进战斗打一回合再来 |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| `PlayerCombatState.MaxEnergy` 是**计算属性**，最终值来自 `Hook.ModifyMaxEnergy` | 反编译：`=> (int)Hook.ModifyMaxEnergy(...)` |
| 字段 `Player.MaxEnergy` 只是"基础值"，不等于界面上限 | 12 篇实测：字段 3、界面 4 |
| decimal 返回 10 的机器码模板 | 15 篇 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| 改 `Player.MaxEnergy` 字段能改界面上限 | 12 篇实测过：显示不跟随 |
