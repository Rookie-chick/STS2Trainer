# 28 · 功能 20：游戏速度（0.5x / 2x / 4x）

> [!important] 这是全系列唯一**不用钩子**的功能，也是唯一"我们要主动调游戏方法"的功能
> 前面 19 个都是"拦住游戏，改它的输入/输出"。
> 这个功能反过来：**我们主动调用 `Engine.set_TimeScale(double)`**，让 Godot 引擎整体变快/变慢。
> 手段是"代码洞 + 一次远程调用"，但要放在**每帧都跑的方法**里（否则调一次就够了吗？—— 够，但重进场景会被重置）。
> 热键：`Ctrl+Num 8`

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 全局游戏速度：1x（正常）/ 2x / 4x / 0.5x |
| 验收标准 | ① 动画、结算明显变快 ② 时间显示（若开）变快 ③ 关掉回 1x |
| 热键 | `Ctrl+Num 8` |

## 2. 原理

```csharp
// 游戏里本来就有的加速键（NGame.cs）
double value = Math.Round(Engine.TimeScale + offset, 1);
Engine.TimeScale = value;                       // ← Godot 的全局时间缩放
this.AddChildSafely(NFullscreenTextVfx.Create($"TimeScale:{Engine.TimeScale}"));
```

- `Engine.TimeScale` 是 **Godot 引擎的静态属性**，底层调用原生方法 `Engine.set_TimeScale(double)`。
- 它影响**所有** `_Process/_PhysicsProcess` 的 delta ⇒ 动画、计时都会变快/变慢。
- 我们只要"调一次"就生效，不需要每帧调。

> [!tip] 为什么原版这个功能"没有 AA 补丁"
> 因为它不需要 hook 任何游戏方法——**它就是调引擎 API**。
> 知识库 [[70-拆解-Plus20 Trainer 的 20 个功能与改法]] 里也标注了：这一项大概率是"直接写值/调方法"。

## 3. 我是怎么做的：怎么找出这个方法的（真实路径）

```text
① ILSpy 搜 "TimeScale" → 命中 NGame.cs 里的加速/减速键处理
② 看清它调的是 Engine.TimeScale（Godot 的静态属性）
③ 在 ILSpy 里展开 Godot.Engine → 找到 set_TimeScale(double)
④ ClrMD 找 set_TimeScale 的地址（它是 GodotSharp 程序集里的静态方法）
```

```powershell
# GodotSharp 的方法在堆里不一定有实例 ⇒ 用模块类型表查
dotnet run --project D:\sts2\clr\sts2clr -- <pid> types Godot.Engine
dotnet run --project D:\sts2\clr\sts2clr -- <pid> methods Godot.Engine set_TimeScale
```

> [!warning] 找不到 `Godot.Engine`？
> ClrMD 的类型表有时列不到（本项目遇到过：堆里没实例的类型要靠模块类型表兜底）。
> 备选方案：**hook 游戏自己的加速键处理方法**（`NGame` 里处理 `Ctrl+Num8` 的那个方法），
> 在它里面改 `offset` 参数；或直接找 `NGame` 的实例，调它的方法。
> 再不行就用"写值"的老办法：先正常按一次游戏自带的加速键，用 CE/本工具扫 `TimeScale` 的实际数值，
> 然后**每次都写那个值**（Godot 把 TimeScale 存在原生侧，扫得到就能写）。

## 4. 你该怎么做：代码怎么写

### 4.1 调一个"参数是 double"的静态方法

x64 上 `double` 参数走 **`xmm0`**：

```asm
; 调 Engine.set_TimeScale(2.0)
; （set_TimeScale 没有 this，因为是静态方法）
48 B8 00 00 00 00 00 00 00 40   mov rax,0x4000000000000000   ; 2.0 的 double 位模式
66 48 0F 6E C0                  movq xmm0,rax
48 B8 <set_TimeScale 地址>       mov rax,<addr>
FF D0                           call rax
```

> double 位模式：`1.0 = 0x3FF0000000000000`、`2.0 = 0x4000000000000000`、`4.0 = 0x4010000000000000`、`0.5 = 0x3FE0000000000000`
> 拿不准就用 `BitConverter.DoubleToInt64Bits(2.0).ToString("X")` 现算。

### 4.2 放在哪里执行

两种做法：

| 做法 | 怎么实现 | 说明 |
|---|---|---|
| **A. 每帧钩子里顺手调**（推荐） | 在已有的帧钩子（`NTargetManager._Process`）里加一个动作：`CheckAddr = &一个"期望倍率"的变量`，值不对就调 `set_TimeScale` 并把自己写成"已应用" | 场景切换/重进战斗后会被重置，这样能自动补回 |
| B. 按热键时调一次 | 热键触发时用 `CreateRemoteThread` 在游戏里调一次 | 简单，但重进场景可能失效 |

方案 A 的代码洞片段（接在 08 篇的帧钩子动作格式里）：

```asm
; if (期望倍率 != 已应用值) { Engine.set_TimeScale(期望倍率); 已应用值 = 期望倍率; }
48 B8 <期望倍率地址>        mov rax,&want          ; double
F2 0F 10 00                 movsd xmm0,[rax]
48 B8 <已应用地址>          mov rax,&applied
F2 0F 10 08                 movsd xmm1,[rax]
66 0F 2E C8                 ucomisd xmm1,xmm0
7A xx                       jp  跳过               ; 处理 NaN
74 xx                       je  跳过
F2 0F 11 00                 movsd [rax],xmm0       ; applied = want
48 B8 <set_TimeScale>       mov rax,<addr>
FF D0                       call rax
跳过:
```

> [!danger] 这条链的前提
> `call` 的目标必须是**真方法地址**（不是 `0xFFFF…`）。Godot 的 `set_TimeScale` 是 P/Invoke 到原生层的薄封装，
> 一般已 JIT；拿不到就按第 3 节的备选方案走"写值"。

## 5. 怎么验证

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | `methods Godot.Engine set_TimeScale` | 有地址 |
| 2 | 按 `Ctrl+Num 8` 切到 2x | 动画/结算明显变快 |
| 3 | 再按切 4x / 0.5x | 明显更快/更慢 |
| 4 | 关掉回 1x | 恢复正常 |
| 5 | 进下一场战斗 | 倍率仍保持（方案 A 会自动补） |

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 重进场景后失效 | 又变回 1x | 用方案 A（每帧检查并补） |
| 调到 0 或负数 | 游戏卡死/不动 | 限制在 0.1~4 之间 |
| `Engine.TimeScale` 找不到 | `types Godot.Engine` 空 | 用第 3 节备选：hook 游戏自己的加速键方法，或扫值写值 |
| 调完音频不同步 | 正常现象（音频不走 TimeScale） | 无解，属引擎行为 |

## 7. 三类结论

### ✅ 已验证（机制）

| 结论 | 证据 |
|---|---|
| 游戏自带加速键改的就是 `Engine.TimeScale` | `NGame.cs`：`Engine.TimeScale = Math.Round(Engine.TimeScale + offset, 1)` |
| double 参数走 `xmm0` | x64 ABI |
| 这个功能不需要 hook 游戏方法 | 原版 20 功能表里它没有 AA 补丁（[[70-拆解-Plus20 Trainer 的 20 个功能与改法]]） |

### ❌ 已证伪

无
