# 13 · 功能 5：无限星星（零基础手把手 + 一次真实崩溃的分析）

> [!important] 这篇除了做功能，还讲一个**血泪教训**
> 我在 Trainer 里打开"无限星星"的瞬间，**游戏进程直接消失**，没有任何托管异常日志。
> 根因：我们的代码洞里"调用游戏方法"时，如果那个方法**抛异常**，异常穿不过我们这段**没有 unwind 信息**的裸机器码 ⇒ 进程被杀。
> 结论：**代码洞里只调"最轻、最不可能抛"的方法**。这篇教你怎么判断和替换。
> 热键：`Num 4`

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 星星锁在 99，星费卡永远够用；左下金色星星显示 99 |
| 验收标准 | ① 星星图标出现并显示 `99` ② 外部把 `_stars` 写成 0，600ms 内回 99 ③ 游戏不崩 |
| 热键 | `Num 4` |

## 2. 原理：三层，三种刷新方式

```csharp
// ① PlayerCombatState._stars（ClrMD 0x64 → 真实 0x6C）
public int Stars { get => _stars; private set { if (_stars != value) { ... StarsChanged?.Invoke(old,new); } } }

// ② NStarCounter._Process：★每帧轮询刷数字（和血/金/能量相反！）
public override void _Process(double delta)
{
    _lerpingStarCount = MathHelper.SmoothDamp(_lerpingStarCount, _player.PlayerCombatState.Stars, ref _velocity, 0.1f, delta);
    SetStarCountText(Mathf.RoundToInt(_lerpingStarCount));      // ← 数字自己会刷
}

// ③ 但"显隐"只在事件里更新
private void OnStarsChanged(int oldStars, int newStars) { UpdateStarCount(old,new); RefreshVisibility(); }

// ④ ★RefreshVisibility 很轻，只碰 Visible
private void RefreshVisibility()
{
    if (_player == null) { base.Visible = false; return; }
    int stars = _player.PlayerCombatState.Stars;
    base.Visible = base.Visible || _player.Character.ShouldAlwaysShowStarCounter || stars > 0;
}

// ⑤ 而 OnStarsChanged 会走 UpdateStarCount → SetStarCountText → 碰 _hsv（ShaderMaterial）
private void SetStarCountText(int stars)
{
    if (_displayedStarCount != stars)
    {
        _displayedStarCount = stars;
        _label.AddThemeColorOverride(...);
        _label.Text = $"[center]{stars}[/center]";
        if (stars == 0) { _hsv.SetShaderParameter(_s, 0.5f); ... }   // ← _hsv 某些时刻是 null
        else { _hsv.SetShaderParameter(_s, 1f); ... }
    }
}
```

### 2.1 崩溃现场（真实）

```text
$ python tools\f01_drive.py key 0x64      # 按 Num 4 打开"无限星星"
游戏存活: False
trainer 日志: [开] 无限星星
游戏日志: 无异常、无堆栈 —— 进程直接没了
```

### 2.2 为什么会这样

```text
我们的代码洞 = 手写的机器码，没有 .NET 的"异常展开信息(unwind info)"
游戏方法内部抛出 NullReferenceException（_hsv 为 null）
  → CLR 要往上找谁来 catch
  → 展开到我们这段裸机器码时找不到帧信息
  → 直接 FailFast / 访问违例：进程被终止
```

### 2.3 解法：把"调用目标"换成最轻的那个

| 候选 | 做了什么 | 安全性 |
|---|---|---|
| `OnStarsChanged(old,new)` | 动画 + 刷文字 + 刷显隐（碰 `_hsv`） | ✗ 会抛 NRE |
| `SetStarCountText(int)` | 刷文字 + 碰 `_hsv` | ✗ 同样危险 |
| **`RefreshVisibility()`** | **只碰 `Visible`** | ✅ 本项目最终用它 |
| 不调（只写字段） | —— | ✅ 但星星图标可能一直不显示（显隐没刷新过） |

数字本来由 `_Process` 每帧刷，所以我们只需要"让它显形" ⇒ 调 `RefreshVisibility` 就够。

## 4. 你该怎么做（在 Trainer 里加"无限星星"）

### 4.1 登记（`Game.cs`）

```csharp
public const int OFF_PCS_STARS = 0x6C;          // PlayerCombatState._stars（ClrMD 0x64 + 8）
public const int OFF_PCS_STARSCHANGED = 0x30;   // StarsChanged 委托（ClrMD 0x28 + 8）

StarUi = FindNodeOwnedBy(T_STAR, OFF_COUNTER_PLAYER, OFF_COUNTER_PLAYER);
FnStarVisible = Method(T_STAR, "RefreshVisibility");       // ★优先用轻的
FnOnStarsChanged = Method(T_STAR, "OnStarsChanged");       // 备查（不安全）
if (FnOnStarsChanged == 0) FnOnStarsChanged = DelegateFn(Pcs, OFF_PCS_STARSCHANGED, out _);
```

> [!tip] 又一个"委托取入口"的用处
> `OnStarsChanged` 常常是 `0xFFFF…`（未 JIT）。这时读 `PlayerCombatState.StarsChanged`（真实偏移 **0x30**）的委托对象，
> `+0x08` 是 `_target`（真正在场景里的那个节点），`+0x18` 是入口。**调一次 precode 还会促使它 JIT**，下次 ClrMD 就能直接查到。

### 4.2 加一条 Action（`Program.cs`）

```csharp
new Hook.Action{
    Name      = "无限星星",
    FlagAddr  = F(3),                        // Num 4
    CheckAddr = g.Pcs + Game.OFF_PCS_STARS,
    Target    = STAR_VALUE,                  // 99
    WriteAddr = g.Pcs + Game.OFF_PCS_STARS,
    CallThis  = g.StarUi,
    CallFn    = g.FnStarVisible,             // ★RefreshVisibility（不要用 OnStarsChanged）
},
```

### 4.3 热键

```csharp
(VK_NUMPAD4, false),   // Num 4
```

## 6. 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一开星星游戏就消失（无日志） | 代码洞里调到了会抛异常的方法 | 换成 `RefreshVisibility`；见 2.3 表格 |
| 数字不出现 | 只写了字段、显隐没刷新 | 补一次"轻量调用" |
| 数字出现但不是 99 | `_Process` 用 SmoothDamp 追值 | 等 0.3~1 秒自然追上 |
| `StarVisible=0` | 方法没 JIT | 进战斗后再装，或改用委托法 |

## 7. 回滚

按 `Q` 还原补丁；强杀则重启游戏（补丁不落盘）。

## 8. 三类结论

### ✅ 已验证

| 结论 | 证据 |
|---|---|
| `_stars` 真实偏移 **0x6C**、`StarsChanged` 委托 **0x30** | 字段/委托 dump + 显示 99 |
| 星星数字是**每帧轮询**刷的 | `NStarCounter._Process` 里 `SmoothDamp` + `SetStarCountText` |
| 显隐靠事件 ⇒ 只写字段不显示 | 只写 3 时画面无星星；换 `RefreshVisibility` 后出现 |
| **代码洞里调"会抛异常的方法"会直接崩进程** | 打开 OnStarsChanged 版本后游戏瞬间消失，无异常日志 |
| 换成 `RefreshVisibility` 就稳定 | 反复开关 5 次以上不崩 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| 只写 `_stars` 就能让星星出现 | 数值进去了，图标不显示 |
| 所有 HUD 都是纯事件驱动 | 星星数字是每帧轮询 |
| 代码洞里调任何托管方法都安全 | 只要目标方法抛异常，进程就死（裸机器码没有 unwind 信息） |
