# 26 · 功能 18：最高分数

> [!important] 这一篇除了改返回值，还讲一个**容易忽略的副作用**：分数会解锁"纪元"
> 原版说明里有一句："每次 run 只能解锁一个 Epoch，超出丢弃"。
> 也就是：分数调太高**不会**让你一次解锁一堆内容——游戏有保护。
> 热键：`Ctrl+Num 6`

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 一局结束时的分数变成一个大数（用于解锁/展示） |
| 验收标准 | ① 结算界面分数是个大数 ② 没有崩溃/卡死 ③ 关掉恢复真实分数 |
| 热键 | `Ctrl+Num 6` |

## 2. 原理

```csharp
// MegaCrit.Sts2.Core.Runs.Metrics/ScoreUtility.cs
public static int CalculateScore(IRunState runState, bool won) { ... return score; }   // ← int
public static int CalculateScore(SerializableRun run, bool won) { ... }               // 重载
```

⇒ 让 `CalculateScore` 返回一个大数（例如 999999）即可。

> [!warning] 有两个重载，别搞混
> 一个吃 `IRunState`（本局内存态），一个吃 `SerializableRun`（存档态）。
> 结算界面通常用内存态那个；保险起见**两个都挂**。

## 3. 我是怎么做的：怎么找出这个方法的（真实路径）

```text
① ILSpy 搜 "CalculateScore" → 命中 ScoreUtility 的两个重载
② 返回 int ⇒ 强制返回目标
③ 顺手看一眼调用点：结算界面/RunHistory 记录
④ ClrMD 确认地址（结算时才算，平时可能未 JIT → 延迟安装）
```

```powershell
dotnet run --project D:\sts2\clr\sts2clr -- <pid> methods MegaCrit.Sts2.Core.Runs.ScoreUtility CalculateScore
```

## 4. 你该怎么做：代码怎么写

```csharp
// 两个重载都要（ClrMD 会把同名的都列出来，注意区分参数个数）
var scoreOrig1 = Hook.InstallForceReturnHook(h, FnScoreState, F(16), 999999);
var scoreOrig2 = Hook.InstallForceReturnHook(h, FnScoreRun,  F(16), 999999);
```

生成的机器码：

```asm
B8 3F 42 0F 00        mov eax,999999
C3                    ret
```

### 4.1 怎么区分重载（关键技巧）

```text
methods 命令会打印：
  CalculateScore native=0x7FF7xxxx       ← 第一条
  CalculateScore native=0x7FF7yyyy       ← 第二条
CLR 不打印参数表，所以：
  ① 用 ILSpy 看源码里哪个是 (IRunState, bool)
  ② 或者在 ClrMD 里读 ClrMethod 的签名（进阶：m.Signature）
  ③ 最省事：两个都挂上，反正返回值一样
```

## 5. 怎么验证

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | 装完 `raw <入口1> 16` / `raw <入口2> 16` | 都是 `E9 …` |
| 2 | 打完一局（或直接放弃本局） | 结算分数 999999 |
| 3 | 看历史记录（时间线） | 分数也是大数 |
| 4 | `Ctrl+Num 6` 关掉再打一局 | 恢复真实分数 |

> [!warning] 别指望"一次解锁一堆"
> 分数过高时游戏仍按"每次 run 只解锁一个 Epoch"的规则走，多的会被丢弃（原版说明原文）。
> 这不是 bug，是游戏自身的保护逻辑。

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 只挂了一个重载 | 结算分数没变（走的是另一个） | 两个都挂 |
| 未 JIT | 0xFFFF | 延迟安装（14 篇） |
| 分数太大导致溢出 | 结算界面显示负数 | 用 999999 这类"安全的大数"，别用 int.MaxValue |
| 关掉后历史记录没变 | 历史是当时写进去的 | 只影响"之后"的结算 |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| 分数由 `ScoreUtility.CalculateScore(IRunState, bool)`（及序列化重载）计算 | 反编译源码 |
| 返回 int ⇒ `mov eax,值; ret` | x64 ABI |
| 高分会受"每局只解锁一个 Epoch"限制 | 原版功能说明（[[70-拆解-Plus20 Trainer 的 20 个功能与改法]]） |

### ❌ 已证伪

无

### ⏳ 待验证

| 结论 | 怎么验 |
|---|---|
| 结算分数 = 999999 | 跑完一局看结算 |
| 两个重载都要挂 | 只挂一个对比 |
| 长局不崩 | 连跑两局 |
