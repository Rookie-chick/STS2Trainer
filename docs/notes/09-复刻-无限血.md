## 0. 先看全貌：我们要干的事只有 4 步

```text
① 让程序知道"玩家在哪、血量字段在对象的第几个字节"     → 用 ClrMD 问活着的游戏进程
② 知道"血变了画面才变"这句话是错的/对的                → 读反编译源码（ILSpy）
③ 找一个"每帧都会执行的方法"，在它入口插一段自己的机器码 → 传统 inline hook
④ 自己的代码里：血不满就写满 → 调游戏自己的刷新方法 → 跳回原方法
```

**结果**：顶栏血量恒为 `9999/9999`，外部把血改成 1，一帧内被补回。

| 你会学到 | 对应小节 |
|---|---|
| 装 .NET SDK / ILSpy / 建 C# 工程 | 第 2~4 节 |
| 怎么拿游戏 pid、怎么确认"能附加" | 第 3、6 节 |
| 怎么"按类型名"找对象、读字段、验证偏移对不对 | 第 7 节 |
| 为什么直接改内存没用（做实验看） | 第 8 节 |
| 怎么在反编译源码里找"刷新 UI 的那个方法" | 第 9 节 |
| 怎么写机器码、为什么必须保存/还原寄存器 | 第 10 节 |
| 怎么验证、崩了怎么办、怎么全撤 | 第 11~13 节 |

## 1. 四个名词，用类比讲清楚

| 名词 | 类比 | 在这个游戏里具体指什么 |
|---|---|---|
| **进程 / pid** | 一间正在营业的店铺，pid 是门牌号 | `SlayTheSpire2.exe` 的进程号，如 12596 |
| **对象 / 字段 / 偏移** | 一个储物柜（对象）里有很多格子，**偏移**就是"第 0x84 号格子" | 玩家角色 = 一个 `Creature` 对象；`+0x84` 格子里放的就是当前血量（int32，4 字节） |
| **JIT** | 厨师第一次接到这道菜才现学做法 | C# 方法第一次被调用时才编译成机器码；没调用过就**没有地址**（ClrMD 会显示 `0xFFFFFFFFFFFFFFFF`） |
| **inline hook** | 在别人家门口贴一张"先到隔壁房间"的纸条 | 把方法开头 5 个字节改成 `jmp 我们的代码`，我们的代码干完活再跳回去 |

### 5.2 `Program.cs`

```csharp
// ============================================================================
//  sts2hp —— 杀戮尖塔 2「无限血」最小示例（零基础可照抄）
//
//  用法（在 PowerShell 里，先 cd 到本工程所在目录）：
//      dotnet run -- <游戏pid>            安装：血量锁 9999
//      dotnet run -- <游戏pid> 50000      安装：血量锁 50000
//      dotnet run -- <游戏pid> poke 1     验证：把血强行写成 1，看会不会被补回
//
//  它做三件事：
//      ① 找到"玩家对象"和它身上的"血量字段"
//      ② 找到"顶栏血量文字"的刷新方法（NTopBarHp.UpdateHealth）
//      ③ 找一个每帧都会执行的方法当"挂点"（NTargetManager._Process），
//         在它的入口打一个 5 字节跳转，跳到我们自己的代码里，
//         代码里：血不满 → 写满 → 调一次刷新方法 → 再跳回原方法
// ============================================================================

using System;
using System.Collections.Generic;
using System.Text;
using Microsoft.Diagnostics.Runtime;

class Prog
{
    // ---- 这两个类型名是从反编译源码里抄来的（decomp\full 下搜类名） ----
    const string T_PLAYER = "MegaCrit.Sts2.Core.Entities.Players.Player";
    const string T_CREATURE = "MegaCrit.Sts2.Core.Entities.Creatures.Creature";
    const string T_HPBAR = "MegaCrit.sts2.Core.Nodes.TopBar.NTopBarHp";   // 注意命名空间是小写 sts2
    const string T_TARGETMGR = "MegaCrit.Sts2.Core.Nodes.Combat.NTargetManager";

    // ---- 字段真实偏移 = ClrMD 报的 offset + 8（为什么 +8 见教程第 7.3 节） ----
    const int OFF_PLAYER_CREATURE = 0x68;  // Player.Creature
    const int OFF_CUR_HP = 0x84;           // Creature._currentHp
    const int OFF_MAX_HP = 0x88;           // Creature._maxHp
    const int OFF_BAR_PLAYER = 0x58;       // NTopBarHp._player

    static DataTarget dt;
    static ClrRuntime rt;
    static Dictionary<string, List<ClrObject>> heap;

    static void Main(string[] args)
    {
        Console.OutputEncoding = Encoding.UTF8;
        if (args.Length < 1)
        {
            Console.WriteLine("用法: dotnet run -- <游戏pid> [血量]");
            Console.WriteLine("      dotnet run -- <游戏pid> poke <值>");
            return;
        }
        int pid = int.Parse(args[0]);

        Console.WriteLine("【1】连接游戏进程 pid=" + pid);
        dt = DataTarget.AttachToProcess(pid, suspend: false);
        rt = dt.ClrVersions[0].CreateRuntime();
        Console.WriteLine("     CLR 版本 = " + dt.ClrVersions[0].Version + "（能打印出来就说明连上了）");

        Console.WriteLine("【2】扫描托管堆（第一次会花几秒）");
        BuildHeap();
        Console.WriteLine("     堆里共 " + heap.Count + " 种类型");

        if (args.Length > 2 && args[1] == "poke")
        {
            Poke(pid, int.Parse(args[2]));
            return;
        }
        int hpValue = args.Length > 1 ? int.Parse(args[1]) : 9999;
        Install(pid, hpValue);
    }

    // ---------------------------------------------------------------- 堆缓存
    static void BuildHeap()
    {
        heap = new Dictionary<string, List<ClrObject>>();
        foreach (var obj in rt.Heap.EnumerateObjects())
        {
            var t = obj.Type;
            if (t == null || t.Name == null) continue;
            if (!heap.TryGetValue(t.Name, out var list)) { list = new List<ClrObject>(); heap[t.Name] = list; }
            list.Add(obj);
        }
    }

    static List<ClrObject> Of(string typeName)
    {
        return heap.TryGetValue(typeName, out var l) ? l : new List<ClrObject>();
    }

    // ---------------------------------------------------------------- 读内存小工具
    static long ReadI64(ulong addr)
    {
        var buf = new byte[8];
        if (dt.DataReader.Read(addr, buf) != 8) return 0;
        return BitConverter.ToInt64(buf, 0);
    }

    static int ReadI32(ulong addr)
    {
        var buf = new byte[4];
        if (dt.DataReader.Read(addr, buf) != 4) return -1;
        return BitConverter.ToInt32(buf, 0);
    }

    // ---------------------------------------------------------------- 找玩家
    static ulong FindPlayerAndCreature(out ulong creature)
    {
        creature = 0;
        int n = 0;
        foreach (var obj in Of(T_PLAYER))
        {
            n++;
            ulong p = obj.Address;
            ulong c = (ulong)ReadI64(p + OFF_PLAYER_CREATURE);
            Console.WriteLine("     Player#" + n + " 地址=0x" + p.ToString("X") + "  Creature=0x" + c.ToString("X"));
            if (c > 0x10000 && creature == 0) creature = c;
        }
        if (creature == 0) return 0;
        foreach (var obj in Of(T_PLAYER)) return obj.Address;
        return 0;
    }

    static ulong FindBar(ulong player)
    {
        foreach (var obj in Of(T_HPBAR))
        {
            var t = obj.Type;
            if (t == null || t.Name != T_HPBAR) continue;
            ulong pl = (ulong)ReadI64(obj.Address + OFF_BAR_PLAYER);
            Console.WriteLine("     NTopBarHp 实例=0x" + obj.Address.ToString("X") + "  _player=0x" + pl.ToString("X"));
            if (pl == player) return obj.Address;
        }
        return 0;
    }

    static ulong MethodAddr(string typeName, string methodName)
    {
        if (!heap.TryGetValue(typeName, out var list) || list.Count == 0)
        {
            Console.WriteLine("     ✗ 堆里找不到类型 " + typeName);
            return 0;
        }
        foreach (var m in list[0].Type.Methods)
        {
            if (m.Name != methodName) continue;
            Console.WriteLine("     " + methodName + " native=0x" + m.NativeCode.ToString("X"));
            if (m.NativeCode > 0x10000 && m.NativeCode != ulong.MaxValue) return (ulong)m.NativeCode;
            Console.WriteLine("       （0xFFFFFFFFFFFFFFFF = 这个方法还没被 JIT，换个方法或等它被调用过）");
        }
        return 0;
    }

    // ---------------------------------------------------------------- 安装
    static void Install(int pid, int hpValue)
    {
        Console.WriteLine("【3】找玩家对象");
        ulong player;
        ulong creature;
        ulong p = FindPlayerAndCreature(out creature);
        if (creature == 0) { Console.WriteLine("     ✗ 没找到 Player/Creature（是不是还没进战斗？）"); return; }
        player = p;
        Console.WriteLine("     ✓ 玩家 Creature = 0x" + creature.ToString("X"));
        Console.WriteLine("     当前血量 = " + ReadI32(creature + OFF_CUR_HP) + "/" + ReadI32(creature + OFF_MAX_HP)
                          + "（应该和画面上的数字一致，不一致就是偏移算错了）");

        Console.WriteLine("【4】找顶栏血量节点 + 它的刷新方法");
        ulong bar = FindBar(player);
        if (bar == 0) { Console.WriteLine("     ✗ 没找到 NTopBarHp 实例"); return; }
        ulong updateHealth = MethodAddr(T_HPBAR, "UpdateHealth");
        if (updateHealth == 0) { Console.WriteLine("     ✗ 没拿到刷新方法地址"); return; }

        Console.WriteLine("【5】找每帧执行的挂点 NTargetManager._Process");
        ulong proc = MethodAddr(T_TARGETMGR, "_Process");
        if (proc == 0)
        {
            Console.WriteLine("     ✗ 没拿到挂点（这个类型要在战斗里才有实例；也可手动传地址）");
            return;
        }

        Console.WriteLine("【6】先把血量上限改成 " + hpValue);
        var h = Hook.Open(pid);
        Hook.WriteI32(h, creature + OFF_MAX_HP, hpValue);
        Console.WriteLine("     回读 = " + Hook.ReadI32(h, creature + OFF_CUR_HP) + "/" + Hook.ReadI32(h, creature + OFF_MAX_HP));

        Console.WriteLine("【7】在挂点上打补丁（跳转到我们的代码）");
        Hook.InstallFrameHook(pid, proc, creature + OFF_CUR_HP, hpValue, bar, updateHealth);

        Console.WriteLine("【8】完成。现在看游戏：顶栏应该是 " + hpValue + "/" + hpValue);
        Console.WriteLine("     验证：dotnet run -- " + pid + " poke 1");
    }

    // ---------------------------------------------------------------- 验证
    static void Poke(int pid, int v)
    {
        ulong creature;
        FindPlayerAndCreature(out creature);
        if (creature == 0) { Console.WriteLine("✗ 没找到 Creature"); return; }
        var h = Hook.Open(pid);
        ulong addr = creature + OFF_CUR_HP;
        Console.WriteLine("写入前 血=" + Hook.ReadI32(h, addr));
        Hook.WriteI32(h, addr, v);
        Console.WriteLine("已强行写成 " + v + "，立刻回读=" + Hook.ReadI32(h, addr));
        System.Threading.Thread.Sleep(500);
        Console.WriteLine("500ms 后回读 血=" + Hook.ReadI32(h, addr) + "  ← 被我们的补丁补回 = 成功");
    }
}
```

### 5.3 `Hook.cs`（注入器，逐行都有注释）

```csharp
// ============================================================================
//  Hook.cs —— 往别人的进程里写机器码（inline hook）
//
//  原理（一张图）：
//
//    游戏原来的方法:                   打完补丁之后:
//    NTargetManager._Process            NTargetManager._Process
//      53                push rbx        E9 xx xx xx xx   jmp 我们的代码洞
//      48 83 EC 20       sub rsp,20      （剩下的字节被 nop 掉）
//      ... 方法正文 ...                   ...
//
//    我们分配的"代码洞"（在挂点附近 2GB 以内，保证 jmp 跳得到）:
//      push rcx / rdx / r8 / r9          ; ★保存现场（被挂钩方法的参数）
//      sub rsp,38h
//      mov rax, 血量字段地址
//      mov edx, [rax]                    ; 读出当前血量
//      cmp edx, 期望值
//      je 跳过
//      mov dword [rax], 期望值            ; ← 把血写满
//      movups [rsp+20h], xmm0            ; 保存浮点参数（_Process 有 double delta）
//      mov rcx, 顶栏节点
//      mov edx, 0 / xor r8d, r8d
//      mov rax, UpdateHealth             ; ← 调游戏的刷新方法
//      call rax
//      movups xmm0, [rsp+20h]
//    跳过:
//      add rsp,38h / pop r9/r8/rdx/rcx    ; ★还原现场（漏了这步游戏会崩！）
//      push rbx                          ; 把被我们覆盖的原指令补回来
//      sub rsp,20
//      jmp 回 挂点+5
// ============================================================================

using System;
using System.Collections.Generic;
using System.Runtime.InteropServices;

static class Hook
{
    const int PAGE_EXECUTE_READWRITE = 0x40;
    const int MEM_COMMIT = 0x1000, MEM_RESERVE = 0x2000;

    [DllImport("kernel32.dll", SetLastError = true)] static extern IntPtr OpenProcess(int access, bool inherit, int pid);
    [DllImport("kernel32.dll", SetLastError = true)] static extern bool ReadProcessMemory(IntPtr h, IntPtr addr, byte[] buf, IntPtr size, out IntPtr read);
    [DllImport("kernel32.dll", SetLastError = true)] static extern bool WriteProcessMemory(IntPtr h, IntPtr addr, byte[] buf, IntPtr size, out IntPtr written);
    [DllImport("kernel32.dll", SetLastError = true)] static extern IntPtr VirtualAllocEx(IntPtr h, IntPtr addr, IntPtr size, int type, int prot);
    [DllImport("kernel32.dll", SetLastError = true)] static extern bool VirtualProtectEx(IntPtr h, IntPtr addr, IntPtr size, int newProt, out int oldProt);
    [DllImport("kernel32.dll", SetLastError = true)] static extern bool FlushInstructionCache(IntPtr h, IntPtr addr, IntPtr size);

    public static IntPtr Open(int pid) { return OpenProcess(0x1F0FFF, false, pid); }

    public static byte[] Read(IntPtr h, ulong addr, int n)
    {
        var b = new byte[n];
        IntPtr got;
        if (!ReadProcessMemory(h, (IntPtr)(long)addr, b, (IntPtr)n, out got)) return null;
        return b;
    }

    public static int ReadI32(IntPtr h, ulong addr)
    {
        var b = Read(h, addr, 4);
        return b == null ? -1 : BitConverter.ToInt32(b, 0);
    }

    public static void WriteI32(IntPtr h, ulong addr, int value)
    {
        IntPtr w;
        WriteProcessMemory(h, (IntPtr)(long)addr, BitConverter.GetBytes(value), (IntPtr)4, out w);
    }

    public static string Hex(byte[] b)
    {
        if (b == null) return "<读不到>";
        var sb = new System.Text.StringBuilder();
        foreach (var x in b) sb.Append(x.ToString("X2")).Append(' ');
        return sb.ToString().Trim();
    }

    // 在目标地址附近（±2GB 内，保证 E9 相对跳转够得着）分配可执行内存
    static ulong AllocNear(IntPtr h, ulong target, int size)
    {
        long t = (long)target;
        for (long d = 0; d < 0x7000_0000L; d += 0x10000)
        {
            for (int s = 0; s < 2; s++)
            {
                long cand = s == 0 ? t - d : t + d;
                if (cand < 0x10000) continue;
                IntPtr p = VirtualAllocEx(h, (IntPtr)cand, (IntPtr)size, MEM_RESERVE | MEM_COMMIT, PAGE_EXECUTE_READWRITE);
                if (p != IntPtr.Zero) return (ulong)p;
            }
        }
        return 0;
    }

    // 一条 x86 指令有多长？只认 .NET 方法序言里常见的那几种（够用）
    static int InsnLen(byte[] b, int i)
    {
        byte op = b[i];
        if (op >= 0x50 && op <= 0x57) return 1;                                   // push/pop r64
        if (op == 0x41 && b[i + 1] >= 0x50 && b[i + 1] <= 0x57) return 2;         // push/pop r8-r15
        if (op == 0x48 && b[i + 1] == 0x83 && (b[i + 2] == 0xEC || b[i + 2] == 0xC4)) return 4;  // sub/add rsp,imm8
        if (op == 0x48 && b[i + 1] == 0x81 && (b[i + 2] == 0xEC || b[i + 2] == 0xC4)) return 7;  // sub/add rsp,imm32
        if (op == 0x48 && b[i + 1] >= 0xB8 && b[i + 1] <= 0xBF) return 10;         // mov r64,imm64
        if (op == 0x4C && b[i + 1] == 0x8B && b[i + 2] == 0xDC) return 3;          // mov r11,rsp
        return -1;
    }

    static int PrologueLen(byte[] head)
    {
        int n = 0;
        while (n < 5)
        {
            int len = InsnLen(head, n);
            if (len <= 0) return -1;
            n += len;
            if (n > 15) return -1;
        }
        return n;
    }

    // ---------------------------------------------------------------- 主入口
    public static void InstallFrameHook(int pid, ulong patchAddr, ulong fieldAddr, int value, ulong callThis, ulong callFn)
    {
        var h = Open(pid);
        if (h == IntPtr.Zero) { Console.WriteLine("     ✗ OpenProcess 失败（用管理员运行 PowerShell）"); return; }

        // 安全闸：地址不像话就别写，否则游戏会崩
        if (patchAddr < 0x10000 || patchAddr == ulong.MaxValue ||
            fieldAddr < 0x10000 || callThis < 0x10000 || callFn < 0x10000 || callFn == ulong.MaxValue)
        {
            Console.WriteLine("     ✗ 地址不合法，已中止（不写任何补丁）"); return;
        }

        var head = Read(h, patchAddr, 16);
        int n = PrologueLen(head);
        if (n < 5)
        {
            Console.WriteLine("     ✗ 读不到能整段覆盖的序言: " + Hex(head)); return;
        }
        var original = new byte[n];
        Array.Copy(head, 0, original, 0, n);
        Console.WriteLine("     挂点前 " + n + " 字节 = " + Hex(original));

        ulong cave = AllocNear(h, patchAddr, 0x1000);
        if (cave == 0) { Console.WriteLine("     ✗ 分配代码洞失败"); return; }

        // ---------------- 拼机器码 ----------------
        var code = new List<byte>();
        void B(params byte[] bs) { code.AddRange(bs); }
        void I32(int v) { code.AddRange(BitConverter.GetBytes(v)); }
        void I64(ulong v) { code.AddRange(BitConverter.GetBytes(v)); }

        // ★★★ 必须先保存现场：rcx/rdx/r8/r9 是"被挂钩方法自己的参数"，
        //     我们借用了它们去调刷新方法，用完必须原样还回去，否则游戏会崩
        B(0x51);                            // push rcx   （this）
        B(0x52);                            // push rdx
        B(0x41, 0x50);                      // push r8
        B(0x41, 0x51);                      // push r9
        B(0x48, 0x83, 0xEC, 0x38);          // sub rsp,38h（0x20 影子空间 + 0x10 存 xmm0 + 对齐）

        B(0x48, 0xB8); I64(fieldAddr);      // mov rax, &_currentHp
        B(0x8B, 0x10);                      // mov edx,[rax]
        B(0x81, 0xFA); I32(value);          // cmp edx, value
        int jeAt = code.Count; B(0x74, 0x00);  // je skip（位移待会补）
        B(0xC7, 0x00); I32(value);          // mov dword [rax], value
        B(0x0F, 0x11, 0x44, 0x24, 0x20);    // movups [rsp+20h], xmm0（_Process 的 double 参数）
        B(0x48, 0xB9); I64(callThis);       // mov rcx, 顶栏节点
        B(0x31, 0xD2);                      // xor edx,edx
        B(0x45, 0x31, 0xC0);                // xor r8d,r8d
        B(0x48, 0xB8); I64(callFn);         // mov rax, UpdateHealth
        B(0xFF, 0xD0);                      // call rax
        B(0x0F, 0x10, 0x44, 0x24, 0x20);    // movups xmm0,[rsp+20h]
        int skipAt = code.Count;
        code[jeAt + 1] = (byte)(skipAt - (jeAt + 2));   // 补 je 的位移

        // ★ 还原现场
        B(0x48, 0x83, 0xC4, 0x38);          // add rsp,38h
        B(0x41, 0x59);                      // pop r9
        B(0x41, 0x58);                      // pop r8
        B(0x5A);                            // pop rdx
        B(0x59);                            // pop rcx

        foreach (var b in original) B(b);    // 补回被覆盖的原指令

        int jmpAt = code.Count;
        B(0xE9); I32(0);                     // jmp 回 patchAddr+n
        int back = (int)((long)(patchAddr + (ulong)n) - (long)(cave + (ulong)jmpAt + 5));
        var rb = BitConverter.GetBytes(back);
        code[jmpAt + 1] = rb[0]; code[jmpAt + 2] = rb[1]; code[jmpAt + 3] = rb[2]; code[jmpAt + 4] = rb[3];

        IntPtr w;
        if (!WriteProcessMemory(h, (IntPtr)(long)cave, code.ToArray(), (IntPtr)code.Count, out w))
        { Console.WriteLine("     ✗ 写代码洞失败"); return; }

        // ---------------- 打补丁 ----------------
        var patch = new byte[n];
        patch[0] = 0xE9;
        var d = BitConverter.GetBytes((int)((long)cave - (long)(patchAddr + 5)));
        patch[1] = d[0]; patch[2] = d[1]; patch[3] = d[2]; patch[4] = d[3];
        for (int i = 5; i < n; i++) patch[i] = 0x90;      // 多出来的补 nop

        int oldProt;
        VirtualProtectEx(h, (IntPtr)(long)patchAddr, (IntPtr)n, PAGE_EXECUTE_READWRITE, out oldProt);
        WriteProcessMemory(h, (IntPtr)(long)patchAddr, patch, (IntPtr)n, out w);
        int tmp;
        VirtualProtectEx(h, (IntPtr)(long)patchAddr, (IntPtr)n, oldProt, out tmp);
        FlushInstructionCache(h, (IntPtr)(long)patchAddr, (IntPtr)n);   // 告诉 CPU 指令变了

        Console.WriteLine("     代码洞 0x" + cave.ToString("X") + "（" + code.Count + " 字节）");
        Console.WriteLine("     代码洞内容: " + Hex(code.ToArray()));
        Console.WriteLine("     补丁: " + Hex(patch) + "   回读: " + Hex(Read(h, patchAddr, n)));
        Console.WriteLine("     ✓ 补丁已生效");
    }
}
```

## 7. 关键概念：怎么"按名字"找到数据（这段是外挂的核心）

### 7.1 为什么要问"活着的进程"

```text
sts2.dll（磁盘文件）   只有：类名 / 字段名 / 方法名 / 签名
                        ✗ 没有"字段在对象里的第几个字节"（那是运行时才能算的）
游戏跑起来以后         CLR 给每个类型算好内存布局 → 对象被分配在托管堆上
⇒ 想要"偏移"和"地址"，只能问活着的进程
```

### 7.2 ClrMD 怎么回答我们

```csharp
dt = DataTarget.AttachToProcess(pid, suspend: false);   // 附加（不暂停游戏）
rt = dt.ClrVersions[0].CreateRuntime();                 // 拿到运行时
foreach (var obj in rt.Heap.EnumerateObjects())         // 遍历堆上所有对象
    obj.Type.Name;                                      // 每个对象的类型名（字符串）
```

- 想要某个类型的所有实例：遍历一遍，比对 `obj.Type.Name == "全名"`
- 想要实例里的字段：`obj.Address + 偏移` 然后用 `ReadProcessMemory` 读 4/8 字节
- 想要方法地址：`type.Methods` 里找 `m.Name == "方法名"`，看 `m.NativeCode`

### 7.3 ★ 最容易踩的坑：ClrMD 报的偏移要 +8

上一版教程直接把 ClrMD 的 offset 当真实偏移，结果**一次都没打中**。原因：

```text
托管对象的内存布局：
  +0x00  MethodTable 指针（类型信息）   ← ClrObject.Address 指向这里
  +0x08  第一个字段
  +0x0C  第二个字段 …

ClrMD 的 ClrInstanceField.Offset 是"相对字段区起点(+8)"算的 ⇒ 真实偏移 = 报的值 + 8
```

**怎么自己验证（必做，30 秒）**：

1. 用 ClrMD 找到 `Creature` 实例，记下它的地址 `A`
2. 读 `A+0x84` 的 int32，打印出来
3. 把程序和游戏画面上的血量对一下：**一样 ⇒ 你的偏移对了**

本作用真实数字验证过的对照表：

```text
Creature  +0x84 _currentHp   +0x88 _maxHp   +0x80 _block
Player    +0x68 <Creature>   +0xE8 _gold
NTopBarHp +0x58 _player
（ClrMD 分别报 0x7C / 0x80 / 0x78 / 0x60 / 0xE0 / 0x50，都要 +8）
```

> [!tip] 还有一条铁证：机器码
> 反编译里 `Creature.set_Block` 的机器码是 `44 8B 81 80 00 00 00`（= `mov r8d,[rcx+0x80]`），
> 而 ClrMD 说 `_block` 在 `0x78` —— 差的正是 8。**代码不会说谎。**

## 8. 实验：为什么"直接改内存"没用（先做这一步再看代码）

### 8.1 用我们的工具直接改血

```powershell
dotnet run -- 12596 poke 1
```

```text
写入前 血=9999
已强行写成 1，立刻回读=1        ← 确实写进去了
500ms 后回读 血=9999            ← 但被补丁补回来了（因为我们装了钩子）
```

**如果没装钩子**（重启游戏后只跑 poke），你会看到：`已强行写成 1，回读=1`，**但游戏画面还是 38/82**。
这就是本功能第一版失败的现场。

### 8.2 为什么画面不动？读反编译源码就明白了

用 ILSpy 打开 `sts2.dll`，搜 `NTopBarHp`，看到：

```csharp
public void Initialize(Player player)
{
    _player = player;
    _player.Creature.CurrentHpChanged += UpdateHealth;   // ① 只在事件里刷新
    _player.Creature.MaxHpChanged   += UpdateHealth;
    UpdateHealth(0, 0);
}

private void UpdateHealth(int _, int __)
{
    var c = _player.Creature;
    int cur = c.CurrentHp;                               // ② 每次被叫到才读字段
    int max = c.MaxHp;
    _hpLabel.SetTextAutoSize($"{cur}/{max}");             // ③ 把字符串塞进 Label 就完事
}
```

再看 `Creature.CurrentHp` 的 setter：

```csharp
if (_currentHp != value)          // ④ 值没变就不发事件
{
    _currentHp = value;
    this.CurrentHpChanged?.Invoke(old, _currentHp);
}
```

**结论**：UI 不会"每帧去看字段"。它是"事件来了 → 读一次字段 → 写进 Label → 之后再不管"。
我们用 `WriteProcessMemory` 改字段，**等于绕过了 setter，事件不会发**，Label 里永远是上次那个字符串。

> [!important] 所以外挂只有两条路
> 1. **让 setter 跑一遍**（改参数/改返回值）—— 适用于"值从参数进来"的方法（见 [[11-复刻-无限护盾]]）
> 2. **替它调一次刷新方法** —— 本功能用这条（`set_CurrentHp` 被 JIT 内联了，挂不了）

### 9.2 找挂点 `NTargetManager._Process`

要求：**每帧都会被调用** + **序言能整段覆盖 ≥5 字节**。

1. ILSpy 搜 `_Process`（`override void _Process(double delta)` 那一类）
2. 挑一个"战斗期间一直活着"的节点，本作用 `NTargetManager`
3. 用我们的工具确认它有机器码 + 序言长度：


```text
NTargetManager::_Process native=0x7FF7CD2F7040
  bytes: 53 48 83 EC 20 48 8B D9 48 8B 43 30 ...
         └63┘ └ 4字节 ┘
         push rbx; sub rsp,20h        ← 1+4 = 5 字节，正好够放一个 jmp
```

> [!tip] "5 字节"是怎么来的
> x86-64 的 `jmp 相对地址`指令固定 **5 字节**（`E9` + 4 字节位移）。
> 所以挂点的开头必须是**若干条完整指令加起来 ≥5 字节**（不能从指令中间切开，否则跳回去时执行到半条指令就崩）。
> 本工程的 `PrologueLen()` 就是干这个：一条一条量，累加到 ≥5 为止。

| 顶栏节点实例 `NTopBarHp` | ClrMD 找 `_player == 我们那个 Player` 的实例 | 调刷新方法时当 `this` |
| `UpdateHealth` 地址 | `type.Methods` 里名字匹配 | 要调的方法 |

## 10. 代码怎么实现（`Hook.cs` 逐段讲解）

### 10.1 四个 Windows API（全部只要名字看懂）

| API | 一句话作用 |
|---|---|
| `OpenProcess` | 拿到操作游戏进程的"句柄"（要管理员） |
| `VirtualAllocEx` | 在**游戏进程里**申请一块内存（放我们的机器码） |
| `WriteProcessMemory` | 往游戏内存写字节 |
| `VirtualProtectEx` | 改内存保护属性（代码段默认只读，要改成可写才能打补丁） |
| `FlushInstructionCache` | 告诉 CPU"这段指令缓存作废了，重新读"（不改这个，补丁可能不生效） |

### 10.2 为什么代码洞要"分配在挂点附近"

`E9` 后面跟的是**相对位移（4 字节有符号）**，最多跳 ±2GB。
如果代码洞被分配到很远的地方，`jmp` 会算错 → 崩。
所以 `AllocNear()` 从挂点开始，以 64KB 为步长向两边试，第一个成功的就用。

### 10.3 为什么要"补回原指令"

我们只借用了方法开头 5 个字节。执行完自己的逻辑后，方法还得继续跑它原来的代码，
所以必须把那 5 个字节（可能是 `push rbx; sub rsp,20h`）**原样执行一遍**，再 `jmp` 回"第 5 字节之后"。

### 10.4 ★ 为什么必须保存 `rcx/rdx/r8/r9` 和 `xmm0`（我在这里崩过一次游戏）

`NTargetManager._Process` 的 `this` 在 `rcx` 里，方法正文还要用它。
我们的代码洞里为了调 `UpdateHealth`，把 `rcx` 改成了"顶栏节点"——
**如果不还回去，方法正文就会拿错 this，直接崩。**

我第一次写精简版时就漏了这步，测试时游戏**当场退出**。加上 push/pop 之后一切正常。

同理 `xmm0` 里放着 `_Process` 的 `double delta` 参数，我们调用别的托管方法会覆盖它，
所以也要 `movups` 存到栈上再读回。

### 10.5 栈对齐（为什么 `sub rsp,38h`）

Windows x64 约定：`call` 之前 `rsp` 必须是 16 的倍数，且要给被调函数留 0x20 字节"影子空间"。
我们的代码：
- 进代码洞时 `rsp % 16 == 8`（因为是被 `call/jmp` 进来的）
- push 4 个寄存器 → 还是 8
- `sub rsp,0x38`（56）→ 变 0（对齐了，其中 0x20 影子空间 + 0x10 存 xmm0 + 8 填充）
- 于是 `call rax` 进去时被调函数看到 `rsp % 16 == 8`，符合约定 ✓

> [!warning] 不对齐会怎样
> 被调方法里一旦用到 SSE 对齐指令（`vmovdqa`）就会崩，而且崩得很随机，很难查。

### 10.6 安全闸（为什么先检查地址）

```csharp
if (patchAddr < 0x10000 || patchAddr == ulong.MaxValue || ...) { 中止 }
```

ClrMD 用 `0xFFFFFFFFFFFFFFFF` 表示"这个方法没有机器码（没 JIT）"。
我第一版没判断，把这个值当成地址去 `call`，**游戏立刻崩溃**。
现在任何"要 call 的地址"都会先过一遍这种检查，不合法就一个字节都不写。

## 12. 出错了怎么办（按现象查）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `DataTarget.AttachToProcess` 抛异常 | 游戏没加载 .NET / 权限不够 | 用 3.1 的参数启动；PowerShell 用管理员 |
| `堆里共 0 种类型` | 附加到了错的进程 | 确认 pid 是 `SlayTheSpire2.exe` |
| `当前血量 = 38/82` 和画面不一致 | 偏移错了 | 记住 **ClrMD 报的 +8**；用 `Player+0xE8` 金币交叉验证 |
| `UpdateHealth native=0xFFFFFFFFFFFFFFFF` | 方法还没被 JIT | 让游戏进一次战斗、让血量变一次，再跑 |
| `✗ 读不到能整段覆盖的序言` | 挂点开头指令太短/不认识 | 换一个 `_Process`；或自己补 `InsnLen` 的规则 |
| 打完补丁游戏**立刻退出** | 地址非法（常见：把 `0xFFFF…` 当地址）/ 没保存寄存器 | 看第 10.4、10.6 节；确认安全闸生效 |
| 补丁装了但画面不变 | 挂点没被调用 / 刷新方法选错 | 换挂点（换成每帧必跑的）；确认刷新方法里真的 `SetTextAutoSize` |
| 一切正常但过一会儿失效 | .NET **分层编译**把它重新 JIT 到别处 | 重新跑一次工具；或换更稳定的挂点 |
| 想验证"到底打中没打中" | —— | 读完 `补丁: E9 …` 那行，再 `poke` 看回读 |

### 两次崩溃的教训（都写进第 12 节排错表了）

1. **把 ClrMD 的"未 JIT"哨兵 `0xFFFFFFFFFFFFFFFF` 当成地址去 `call`** ⇒ 进程直接退出。
   ⇒ 任何要 `call` 的地址，先判断 `>= 0x10000` 且 `!= ulong.MaxValue`。
2. **代码洞里改了 `rcx` 没还回去** ⇒ 被挂钩的方法拿错 `this` ⇒ 崩溃。
   ⇒ 入口处 `push rcx/rdx/r8/r9`，出口 `pop` 回来。

## 14. 三类结论

### ✅ 已验证

| 结论 | 证据 |
|---|---|
| 本教程两份代码**可直接编译运行** | `dotnet build` 成功；`dotnet run -- 12596` 全流程输出与文中一致 |
| `_currentHp` 真实偏移 **0x84**、`_maxHp` **0x88** | 读出 38/82 与画面一致；机器码 `8B 9A 84 00 00 00` |
| 只写字段不改画面（UI 事件驱动） | 未装钩子时 poke 后画面不动；源码 `UpdateHealth` 只在事件里调 |
| 帧钩子方案可行 | 顶栏变 `9999/9999`，poke 1 秒回 9999 |
| 不保存 `rcx` 会崩游戏 | 精简版第一次测试：游戏当场退出；补上 push/pop 后正常 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| ClrMD 报的 offset 能直接用 | 全部差 8，写 0x7C/0x80 打不中血 |
| 挂 `Creature.set_CurrentHp` | native=`0xFFFFFFFFFFFFFFFF`（被 JIT 内联），没有入口可挂 |
| `PostMessage` 发鼠标能点按钮 | Godot 用 raw input，只有 `SendInput` 真点击有效（顺带经验） |

### ⏳ 待验证

|---|---|
