# 25 · 功能 17：药水槽数量

> [!important] 这一篇教"改 int 参数"（最简单的一种改参数）
> 11 篇（护盾）改的是 `edx` 里的 int 参数；这次目标方法叫 `SetMaxPotionCountInternal(int potionSlotCount)`，
> 同样在 `edx` 里 ⇒ 直接把 `edx` 改成 20。**而且它不碰任何 UI 调用，零崩溃风险。**
> 热键：`Ctrl+Num 5`

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 药水槽上限变成 20（原版默认 3） |
| 验收标准 | ① 顶栏药水槽变成 20 格 ② 能捡 20 瓶药水 ③ 关掉后新开一局恢复 3 |
| 热键 | `Ctrl+Num 5` |

## 2. 原理

```csharp
// MegaCrit.Sts2.Core.Entities.Players/Player.cs（节选）
public int MaxPotionSlotCount { get; private set; }
internal void SetMaxPotionCountInternal(int potionSlotCount)   // ← 唯一设置入口
{
    MaxPotionSlotCount = potionSlotCount;
    MaxPotionCountChanged?.Invoke(potionSlotCount);            // 发事件 → UI 自己刷
}
```

- 参数是 `int`，在 x64 上是 **`edx`**（第 2 个参数）。
- 方法内部会发事件 ⇒ **UI 自动更新，不用我们调刷新方法**。

> [!warning] 时机：**开新局/读档前**按（原版说明也这么写）
> 药水槽是在"创建玩家/读档"时初始化的。已经进游戏了再改，只会影响"下次初始化"。
> 所以要**先开钩子，再进游戏**（或读档）。

## 4. 你该怎么做：代码怎么写

用 11 篇的 setter 钩子（`InstallSetterHook`），但把"门禁"放宽成"所有人都改"：

```csharp
// Hook.cs 里已有 InstallSetterHook(h, methodAddr, thisAddr, forcedValue, flagAddr)
// 它会在 this == 指定对象 时把 edx 改成 forcedValue。
// 这里我们干脆不门禁：this 传 0 → 钩子改成"只判开关"
var potionSlotOrig = g.FnSetPotionSlots >= 0x10000
    ? Hook.InstallSetterHook(h, g.FnSetPotionSlots, g.Player, 20, F(15))
    : null;
```

生成的机器码（和 11 篇一样，只是数值变 20）：

```asm
50                        push rax
48 B8 <&flag>             mov  rax,&开关
83 38 00                  cmp  dword [rax],0
74 xx                     je   原样
48 B8 <玩家Player>         mov  rax,玩家
48 39 C1                  cmp  rcx,rax
75 xx                     jne  原样
BA 14 00 00 00            mov  edx,20          ; ★药水槽 = 20
原样:
58                        pop  rax
<原 n 字节>
E9 <rel32>                jmp  回 +n
```

> [!tip] 想"所有玩家都改"（多人）
> 把 `cmp rcx,rax / jne` 两条去掉即可（不门禁）。单机没必要。

## 5. 怎么验证

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | 开钩子（`Ctrl+Num 5`） | 控制台 `[开] 药水槽=20` |
| 2 | **重开一局**（或在主菜单读档） | 顶栏药水槽 20 格 |
| 3 | 捡几瓶药水 | 能超过 3 瓶 |
| 4 | 关掉后重开一局 | 恢复 3 格 |

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 进游戏后才开 | 药水槽还是 3 | 先开钩子再进局/读档 |
| 槽位显示 20 但捡不了 | 另有上限校验（如 `AddPotionFailed`） | 再挂 `AddPotion` 相关校验（进阶） |
| 存档后重开又变 3 | 读档时用存档里的值覆盖 | 保持钩子常开（读档那一下就生效） |

## 7. 三类结论

### ✅ 已验证（方法层面）

| 结论 | 证据 |
|---|---|
| `Player.SetMaxPotionCountInternal(int)` 是药水槽上限的唯一设置入口 | 反编译：构造函数/读档处都调它 |
| 方法内部会 `MaxPotionCountChanged?.Invoke(...)` ⇒ UI 自动刷 | 源码 |
| int 参数在 `edx` | x64 调用约定（11 篇同款） |

无
