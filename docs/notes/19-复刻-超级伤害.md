# 19 · 功能 11：超级伤害 / 一击必杀

> [!important] 这一篇教"改 decimal 参数"（最危险也最有用的一招）
> 15 篇教了**返回** decimal，这一篇教**改参数里的 decimal**：
> 伤害/价格这类数值在 x64 上都是"`rdx` 指向一块 16 字节的 decimal"，改它 = 改实际生效的数值。
> **必须带"对象门禁"**：只改敌人的伤害，否则你自己也会被 9999 打死。
> 热键：`Num 0`

> [!warning] 2026-11-03 修正：原版挂的不是 `LoseHpInternal`
> 我从样本 exe 里重新抽了 `define(address,…)`，原版挂的是
> **`Hook::ModifyDamage`**（两个重载），不是低一层的 `Creature::LoseHpInternal`。
> 两种挂法的差异、以及 `ModifyDamage` 的完整 ABI（decimal 返回值让参数右移一格）见 [[29-踩坑-五个真坑（静态类-残留补丁-未JIT-只写值-decimal右移）]]。
> 下面先讲**原版挂法**（推荐），最后附"低一层"的备选方案。

---

## 1. 目标

| 项 | 内容 |
|---|---|
| 要做的事 | 你打出的任何伤害都变成 9999（基本一击必杀），且**不作用于玩家自己** |
| 验收标准 | ① 用 1 费打击就能秒掉 234 血的敌人 ② 玩家自己受伤正常（不变成 9999） ③ 关掉恢复 |
| 热键 | `Num 0` |

## 2. 原理：为什么选 `LoseHpInternal`

```csharp
// MegaCrit.Sts2.Core.Entities.Creatures/Creature.cs
public DamageResult LoseHpInternal(decimal amount, ValueProp props)   // ← 真正扣血的地方
{
    bool flag = CurrentHp > 0 && amount >= (decimal)CurrentHp;
    int currentHp = CurrentHp;
    ...
    CurrentHp = Math.Max(CurrentHp - num, 0);   // ← 扣血
    ...
}
```

- 它**每个生物**（玩家/敌人）受伤都会走，参数 `amount` 是"这一下要扣多少血"。
- x64 调用约定：`rcx` = `this`（受伤的那个 Creature）、`rdx` = **指向 decimal amount 的指针**、`r8d` = props 枚举。
- 我们的钩子：**如果 `rcx` 不是玩家 ⇒ 把 `[rdx]` 那 16 字节改成 9999**。

> [!tip] 为什么不直接 hook 原版的 `Hook.ModifyDamage`
> 原版挂 `ModifyDamage` 更"正统"（能改卡面显示的数字），但它的签名有 10 个参数（4 个寄存器 + 6 个栈参数），
> 而且**玩家的伤害也会经过它**——一旦你写错门禁，自己就被秒了。
> `LoseHpInternal` 只有 2 个参数、`this` 直接是"受伤者"，**门禁最好写**，适合当教学的第一版。
> 等你熟练了再上 `ModifyDamage`（20 篇讲倍率时会提到它）。

② 看参数：decimal + enum，两个参数 ⇒ rcx/rdx/r8d 清楚

## 4. 你该怎么做：代码怎么写

### 4.0 ★ 原版挂法（推荐）：`Hook::ModifyDamage`

找地址（注意它是**静态类**，堆里没实例，必须按模块类型表查，见 29 篇坑 1）：

```csharp
// Game.cs
var md = Methods("MegaCrit.Sts2.Core.Hooks.Hook", "ModifyDamage");   // 两个重载
FnModifyDamage1 = md.Count > 0 ? md[0] : 0;
FnModifyDamage2 = md.Count > 1 ? md[1] : 0;
```

ABI（因为返回值是 decimal，`rcx` 被隐藏返回缓冲占用，参数整体右移）：

```text
rcx = &ret(decimal)   rdx = IRunState   r8 = ICombatState   r9 = target(受伤者)
栈： [rsp+0x28]=dealer   [rsp+0x30]=&damage(decimal)   [rsp+0x38]=props …
```

机器码（本项目最终版本，压 6 个寄存器后 `&damage` 变成 `[rsp+0x60]`）：

```asm
50 53 51 52 41 50 41 51     push rax,rbx,rcx,rdx,r8,r9
4C 8B 44 24 60              mov  r8,[rsp+0x60]      ; &damage
48 8B 1C 24                 mov  rbx,[rsp]          ; target（保存的 r9）
48 39 CB                    cmp  rbx,玩家Creature
74 xx                       je   玩家侧              ; ★ 门禁：玩家走另一条路
41 C7 00 0F 27 00 00        mov  dword [r8],9999    ; 超级伤害
41 C7 40 04 00 00 00 00     mov  dword [r8+4],0
41 C7 40 08 00 00 00 00     mov  dword [r8+8],0
41 C7 40 0C 00 00 00 00     mov  dword [r8+0xC],0
```

> [!tip] 为什么比挂 `LoseHpInternal` 好
> `ModifyDamage` 是**游戏自己算伤害的入口**，改它 ⇒ 卡面预览、力量/易伤等修正都会基于你改后的值重算；
> 挂更底层的 `LoseHpInternal` 只是"最后扣血那一步"，中间那些修正照旧，数值看起来会不一致。

### 4.1 备选：`Creature::LoseHpInternal`（低一层，实现更简单）

```csharp
// rcx = 受伤的 Creature，rdx = &decimal amount
// 门禁：rcx != 玩家 ⇒ 写 9999
```

```asm
C7 02 0F 27 00 00        mov dword [rdx],9999
C7 42 04 00 00 00 00     mov dword [rdx+4],0
C7 42 08 00 00 00 00     mov dword [rdx+8],0
C7 42 0C 00 00 00 00     mov dword [rdx+0xC],0
```

缺点：绕过 `ModifyDamage` 里的各种修正，卡面显示与实际伤害不一致；优点：参数位置最简单（`rdx` 就是 `&amount`）。

### 4.2 decimal 参数的内存布局（和 15 篇一样）

```text
rdx ──► +0x00 lo(int)   低 32 位
        +0x04 mid(int)
        +0x08 hi(int)
        +0x0C flags(int)  scale 在 bit16~23
```

> [!danger] 三条命门
> 1. **必须 push/pop 所有被改的寄存器**（尤其 `rcx`：我们用它当门禁比较对象）
> 2. **必须在指针上写满 16 字节**（只写 lo，`mid/hi/flags` 残留会变成天文数字）
> 3. **必须门禁**：`target == 玩家` 时放行，否则自己也被秒

```csharp
// Hook.cs：改 decimal 参数的钩子
public static byte[] InstallDecimalArgHook(IntPtr h, ulong methodAddr, ulong flagAddr,
                                           ulong playerCreature, int newLo)
{
    var head = Read(h, methodAddr, 16);
    int n = PrologueLen(head);
    var original = new byte[n]; Array.Copy(head, 0, original, 0, n);
    ulong cave = AllocNear(h, methodAddr, 0x1000);

    var c = new List<byte>();
    void B(params byte[] bs) => c.AddRange(bs);
    void I32(int v) => c.AddRange(BitConverter.GetBytes(v));
    void I64(ulong v) => c.AddRange(BitConverter.GetBytes(v));

    B(0x50);                                  // push rax
    B(0x48, 0xB8); I64(flagAddr);             // mov rax,&开关
    B(0x83, 0x38, 0x00);                      // cmp dword [rax],0
    int jeFlag = c.Count; B(0x74, 0x00);      // je 原样（功能关）

    B(0x48, 0xB8); I64(playerCreature);       // mov rax,玩家Creature
    B(0x48, 0x39, 0xC1);                      // cmp rcx,rax       ← rcx = 受伤者
    int jePlayer = c.Count; B(0x74, 0x00);    // je 原样（玩家自己别改！）

    B(0xC7, 0x02); I32(newLo);                // mov dword [rdx],9999
    B(0xC7, 0x42, 0x04); I32(0);              // mov dword [rdx+4],0
    B(0xC7, 0x42, 0x08); I32(0);              // mov dword [rdx+8],0
    B(0xC7, 0x42, 0x0C); I32(0);              // mov dword [rdx+0xC],0

    int origAt = c.Count;
    c[jeFlag + 1] = (byte)(origAt - (jeFlag + 2));   // 两条 je 都跳到"原样"
    c[jePlayer + 1] = (byte)(origAt - (jePlayer + 2));

    B(0x58);                                  // pop rax
    foreach (var b in original) B(b);
    int jmpAt = c.Count; B(0xE9); I32(0);
    // …填 rel32 / 写代码洞 / Patch(入口)…
    return original;
}
```

> [!danger] 三条命门
> 1. **必须 `push rax` / `pop rax`**：我们改了 rax，方法体可能还要用。
> 2. **必须在 `[rdx]` 上写 16 字节**：只写 lo 不够，`mid/hi/flags` 残留会让数值变成天文数字。
> 3. **必须门禁**：`cmp rcx, 玩家Creature` —— 否则玩家的受伤也会被改成 9999（自己秒自己）。

## 5. 怎么验证

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | 装完 `raw <入口> 16` | `E9 …` |
| 2 | 用最便宜的 1 费攻击打敌人 | 敌人**直接死/掉 9999** |
| 3 | 让敌人打你一下 | 你掉的是**正常伤害**（不是 9999）—— 这说明门禁生效 |
| 4 | `Num 0` 关掉再打 | 恢复正常伤害 |
| 5 | 反复开关 3 次 | 不崩 |

> [!tip] 如果敌人没掉那么多
> 说明它先被"格挡"吃掉了。先把 [[11-复刻-无限护盾]] 里护盾钩子的开关关掉，
> 或者直接看 `CurrentHp` 的变化（`player`/`raw` 命令读敌人的血量）。

## 6. 坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 玩家自己也被秒 | 一受击就死 | 门禁写反了（应 `je 原样`，不是改） |
| 敌人掉血变成天文数字/负数 | 只写了 lo | 16 字节全写 |
| 一开就崩 | 忘了 push/pop rax，或地址非法 | 检查安全闸 + 保存寄存器 |
| 挂不上（0xFFFF） | 方法没 JIT 或 ClrMD 枚举不全 | 用 `find` 特征码扫，或改挂 `CreatureCmd.Damage` |

## 7. 三类结论

### ✅ 已验证（机制层面）

| 结论 | 证据 |
|---|---|
| `Creature.LoseHpInternal(decimal, ValueProp)` 是"真正扣血"那一层 | 反编译注释明确说 hooks 在 `CreatureCmd.Damage`，本方法是底层 |
| x64 上 decimal 参数只传指针（`rdx`） | ABI；15 篇的返回值版本可对照 |
| 改 16 字节即可改数值 | decimal 布局（lo/mid/hi/flags） |
| 必须做 this 门禁 | 否则玩家同链路受伤会被一起改 |

### ❌ 已证伪

| 结论 | 现象 |
|---|---|
| ClrMD 一定列得出 `LoseHpInternal` | 本机 `methods` 有时查不到（枚举不全），要备选方案 |
